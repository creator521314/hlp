# hlp v0.2 shell 集成与危险命令熔断设计文档

> 范围：v0.2 —— zsh / bash / fish 三种 shell 集成（`// ` 前缀 + Ctrl+G 原地替换 + 撤销）；危险命令检测 + 可记忆信任（danger.toml）
> 唯一需求来源：`docs/REQUIREMENTS.md`（v0.2 草案），§13 决策记录优先级最高。本文档自包含，实现模型无需查看任何聊天记录。
> 前置：v0.1 引擎已实现（参数 → Provider(ollama) → stdout 单行命令，`--one-line` stdout 纯净协议，退出码 2/3/4/5）。本文档凡引用 v0.1 行为处均重述契约，不依赖其实现细节。

### 1.3 延迟预算（呼应 §6.1）

| 环节 | 预算 | 说明 |
|---|---|---|
| Ctrl+G → 生成中提示出现 | < 50ms | widget 内同步 zle -M / echo，先于 hlp 调用 |
| hlp 进程启动 + `--one-line` 请求 | v0.1 已有预算（启动 <20ms + LLM 1~3s） | v0.2 不改动 |
| `hlp --check`（危险检测） | < 10ms | 纯本地：读 danger.toml + 规则匹配，无 LLM、无网络 |
| `hlp --trust`（写信任） | < 20ms | 本地文件读写 |
| 撤销（再按 Ctrl+G） | < 5ms | 纯 shell 变量操作，不调 hlp |

§6.1 的"LLM 感知 < 500ms"依赖 v0.3 的 daemon + 流式，v0.2 不背此指标；补偿手段见 §4.1 状态机。

## 2. 模块分解

新增/修改结构（相对 v0.1）：

```
src/
├── main.rs            # 修改：新增 init / --check / --trust 三条本地分发路径
├── cli.rs             # 修改：新增 init 子命令与 --check / --trust 参数
├── danger/            # 新增
│   ├── mod.rs         # DangerLevel / DangerVerdict / check()
│   ├── patterns.rs    # 内置规则表
│   └── trust.rs       # danger.toml 读写
└── integrations/      # 新增
    ├── mod.rs         # init(shell) -> &'static str 分发
    ├── zsh.rs         # zsh 集成脚本模板
    ├── bash.rs
    └── fish.rs
```

**引擎（engine.rs / provider/ / output.rs）零改动**——v0.2 的三个新模式全部不经过 LLM。

### 2.1 `danger/mod.rs`

- 【职责】对一条命令做危险分级判定；组织规则匹配与信任过滤。
- 【公开接口】

```rust
pub enum DangerLevel { Clean, Info, Warning, Fatal }

pub struct DangerVerdict {
    pub level: DangerLevel,       // 信任命中时为 Clean
    pub pattern: Option<&'static str>,   // 命中规则 ID；Clean 为 None
    pub reason: String,           // 人话原因（给用户看），如 "重定向将覆盖 file.txt"
    pub trusted: bool,            // 命中规则但已在信任列表 → level 已折叠为 Clean
}

/// 对命令做危险检查。纯函数（信任表作为参数传入，IO 由调用方负责）。
pub fn check(command: &str, trust: &TrustList) -> DangerVerdict;
```

- 【输入/输出契约】
  - `check` 逐条规则匹配，**致命规则优先于警告规则，警告优先于提示**——一条命令同时命中多级时返回最高级（如 `rm -rf / > out` 命中 rm_recursive_root + redirect_overwrite → 返回 fatal + rm_recursive_root）。
  - 命中规则且该规则 ID 在 `trust` 中 → 返回 `level=Clean, trusted=true, pattern=Some(id)`（"后续不再提示"语义，§7.2）。
  - `reason` 上限 80 字符，面向终端用户。
- 【依赖】`patterns.rs`、`trust.rs`。
- 【失败语义】纯函数无 IO，无失败路径。

### 2.2 `danger/patterns.rs`

- 【职责】内置危险规则表（§7.1 初版清单的形式化）。
- 【公开接口】

```rust
pub struct DangerRule {
    pub id: &'static str,        // 稳定 ID，写入 danger.toml 信任列表
    pub level: DangerLevel,
    pub description: &'static str, // 规则说明（--check 输出、文档用）
    pub regex: &'static str,     // 匹配命令的 regex（见决策 1）
}

pub fn builtin_rules() -> &'static [DangerRule];  // 8 条，见 §3.1
```

- 【规则表内容】见 §3.1（含级别分层与边界定义）。
- 【失败语义】静态表，无失败路径。regex 均为编译期字面量，`check` 启动时一次性 `Regex::new`（8 条总编译 <1ms，计入 §1.3 预算）。

### 2.3 `danger/trust.rs`

- 【职责】`~/.config/hlp/danger.toml` 的加载与写入（信任列表的唯一写者）。
- 【公开接口】

```rust
pub struct TrustEntry {
    pub pattern: String,        // 规则 ID
    pub trusted_at: u64,        // Unix 秒（决策 6：不用 chrono）
    pub example: String,        // 触发时的样例命令（人工审查用）
}

pub struct TrustList { pub entries: Vec<TrustEntry> }

impl TrustList {
    pub fn is_trusted(&self, pattern_id: &str) -> bool;
}

/// 读取 danger.toml。文件不存在 → 空 TrustList，不视为错误，不创建文件。
/// 文件存在但语法/字段非法 → Err（退出码 3，提示手动修复路径）。
pub fn load() -> Result<TrustList, HlpError>;

/// 追加一条信任记录并原子写回（先写 .tmp 再 rename）。
pub fn add_trust(pattern_id: &str, example: &str) -> Result<(), HlpError>;
```

- 【写入契约】`add_trust` 是 danger.toml 的**唯一写者**（单写者原则：shell 脚本永远不直接改 TOML）；同 ID 重复调用为幂等（已存在则不动文件，返回 Ok）。
- 【依赖】`serde`、`toml`（序列化能力）、`crate::error`。
- 【失败语义】解析错误直接退出（3）；写入失败（权限/磁盘）→ 直接退出（3），错误信息给出文件路径。

### 2.4 `integrations/mod.rs` + `zsh.rs` / `bash.rs` / `fish.rs`

- 【职责】持有三种 shell 的集成脚本模板；`init` 输出给 stdout 供 `eval "$(hlp init zsh)"` 消费。
- 【公开接口】

```rust
pub enum Shell { Zsh, Bash, Fish }

impl Shell {
    /// 解析子命令参数；非法值由 clap 报错（退出码 2）
    pub fn from_arg(s: &str) -> Option<Shell>;
}

/// 返回完整集成脚本（模板全文见 §3.3，是协议的一部分，逐字交付）
pub fn script(shell: Shell) -> &'static str;
```

- 【输出契约】`hlp init <shell>` 的 stdout = 完整可 eval 的脚本，无其他任何输出；v0.2 模板内嵌 hlp 的绝对调用路径为 `hlp`（依赖用户 PATH；不解析自身 exe 路径——决策 7）。
- 【依赖】无。
- 【失败语义】纯静态模板。

### 2.5 `cli.rs`（修改）与 `main.rs`（修改）

- 【新增参数规格】
  - 子命令 `hlp init <zsh|bash|fish>`：输出集成脚本到 stdout，退出 0。非法 shell 名 → clap 报错退出 2。
  - `hlp --check "<command>"`：本地危险检测，**不走 LLM**。stdout 输出 key=value 判定结果（协议见 §3.2），退出码 = 0（clean/info）/ 10（warning）/ 11（fatal）。
  - `hlp --trust <pattern-id> [--example "<命令>"]`：把规则 ID 写入 danger.toml 信任列表。`--example` 缺省为空串。退出 0；pattern-id 不在内置规则表中 → 退出 12，stderr 列出全部合法 ID。
  - 互斥性：`--check` / `--trust` 与位置参数意图、`--one-line` / `--alt` / `--verbose` 互斥（同时出现 → clap 报错退出 2）；`init` 是子命令，天然与 flags 互斥。
  - v0.1 的 `--one-line` 主形态**行为完全不变**（stdout 纯净契约神圣不可侵犯，见决策 3）。
- 【main 分发】`--check` / `--trust` / `init` 三条路径不构造 Engine、不读 config.toml 的 provider 配置（但 `--check` / `--trust` 读 danger.toml）。加载失败按 v0.1 的 `fail()` 统一出口。
- 【依赖】clap（新增 subcommand 定义）。

## 3. 数据结构与协议

### 3.1 内置危险规则表（8 条）

regex 采用 `regex` crate 语法；匹配对象是**完整命令字符串**（单行）；所有匹配为无大小写敏感。分级依据 REQUIREMENTS §7.1，"尤其指向"类做了两档细化（决策 8）。

| ID | 级别 | 触发条件（regex 意图描述） | reason 模板 |
|---|---|---|---|
| `rm_recursive_root` | fatal | `rm` 带 `-r`/`-f`/`-rf`/`-fr`（含合并短参），且目标含 `/`、`~`、`*`、`$HOME`、`/*`、`~/*`，或目标为 `/usr` `/etc` `/var` `/boot` `/bin` `/lib` `/home` 等系统目录 | `rm 递归删除且目标指向系统级路径` |
| `dd_device` | fatal | `dd` 且参数含 `of=/dev/`（除 `/dev/null`） | `dd 直接写入设备文件` |
| `mkfs` | fatal | 独立词 `mkfs` 开头的命令（`mkfs.ext4` 等） | `mkfs 将格式化文件系统` |
| `rm_recursive` | warning | `rm` 带递归/强制参数，目标为普通路径 | `rm 递归删除普通路径` |
| `redirect_overwrite` | warning | 含单 `>` 重定向（含 `2>`、`&>`），目标非 `>>` 且非 `/dev/null` | `重定向将覆盖 <目标文件>` |
| `chmod_recursive` | warning | `chmod -R 777` 或 `chown -R`，目标指向系统目录 | `递归修改系统目录权限` |
| `pipe_to_shell` | warning | `(curl|wget)` 管道至 `(ba\|)sh`（`... \| sh`、`\| bash`、`\| sudo bash` 等） | `网络内容直接交给 shell 执行` |
| `kill_9_unscoped` | info | `kill -9` 无 PID 参数 | `kill -9 未指定目标进程` |

regex 实现注意事项（写给实现模型）：

- 词边界必须用 `\b`，避免 `grep rm file` 误报 `rm`、`dd` 出现在 `ldd` 中。
- `rm_recursive_root` 的实现拆为两步：先用 regex 找到 `rm` 词及其参数区（到下一个 `;`/`|`/`&&` 边界），再在参数区判目标。纯单 regex 判"参数与目标的组合关系"不可靠。
- `redirect_overwrite` 须排除 `>>`、`2>>`、`>/dev/null`、`2>/dev/null`。
- 引号内的字符串**不排除**（如 `echo "curl x | sh"` 会命中 pipe_to_shell）——已知的误报局限，由信任机制与 info/warning 不阻塞的特性兜底，见遗留风险 #3。

### 3.2 `--check` 的 stdout 协议与退出码

stdout 按行输出 `key=value`，键序固定，值内不含换行。消费方（shell widget）逐行 `grep`/`cut` 解析，无需 JSON 工具：

```
level=clean                          # clean / info / warning / fatal（trusted 时为 clean）
pattern=rm_recursive_root            # 仅命中时输出此行；clean 且非 trusted 时无此行
trusted=true                         # 仅信任命中时输出
reason=rm 递归删除且目标指向系统级路径  # 命中时输出
```

| 场景 | stdout | 退出码 |
|---|---|---|
| 无命中 | `level=clean` | 0 |
| 命中但已信任 | `level=clean` + `pattern=` + `trusted=true` | 0 |
| 命中 info | `level=info` + `pattern=` + `reason=` | 0 |
| 命中 warning | `level=warning` + … | 10 |
| 命中 fatal | `level=fatal` + … | 11 |
| danger.toml 解析失败 | （空） | 3 |

### 3.3 三种 shell 集成脚本模板（逐字交付的协议）

三个模板共用同一交互状态机（见 §4.1），差异只在 shell 原生 API。以下脚本即 `integrations/{zsh,bash,fish}.rs` 的模板全文规格；实现模型逐字嵌入（`hlp` 调用点、消息文案不得改写）。

**zsh（`hlp init zsh`）：**

```zsh
# hlp zsh 集成 —— 在 ~/.zshrc 加入：eval "$(hlp init zsh)"
hlp-replace() {
  # ── 撤销：当前 buffer 是上次生成结果 → 恢复原始意图 ──
  if [[ -n "$hlp_generated" && "$BUFFER" == "$hlp_generated" ]]; then
    BUFFER="$hlp_last_intent"
    CURSOR=${#BUFFER}
    hlp_generated=""
    zle -M "已撤销，恢复意图原文"
    return
  fi
  local intent="${BUFFER#//}"
  intent="${intent#"${intent%%[![:space:]]*}"}"   # 去前导空白
  if [[ -z "$intent" ]]; then
    zle -M "✗ 意图为空"
    return
  fi
  zle -M "… hlp 生成中"
  zle reset-prompt
  local cmd rc
  cmd=$(hlp --one-line "$intent" 2>/dev/null); rc=$?
  if [[ $rc -ne 0 || -z "$cmd" ]]; then
    zle -M "✗ 生成失败（hlp 退出码 $rc）"
    return
  fi
  # ── 危险检查（本地，<10ms）──
  local level pattern
  level=$(hlp --check "$cmd" 2>/dev/null | sed -n 's/^level=//p')
  pattern=$(hlp --check "$cmd" 2>/dev/null | sed -n 's/^pattern=//p')
  if [[ "$level" == "fatal" ]]; then
    local reply
    read "reply?⚠ 致命命令，需完整重新输入以确认: $cmd
确认输入: "
    if [[ "$reply" != "$cmd" ]]; then
      zle -M "✗ 确认失败，已放弃（原始意图保留）"
      return
    fi
    if hlp-confirm-trust "$pattern" "$cmd"; then :; fi
  elif [[ "$level" == "warning" ]]; then
    local reply
    read "reply?⚠ 警告（$pattern），回车采纳 / Ctrl+C 放弃: "
    hlp-confirm-trust "$pattern" "$cmd"
  fi
  hlp_last_intent="$BUFFER"
  hlp_generated="$cmd"
  BUFFER="$cmd"
  CURSOR=${#BUFFER}
  zle -M "✓ 已生成（再按 Ctrl+G 撤销，回车执行）"
}

# 危险确认后询问是否记忆信任（fatal/warning 共用）
hlp-confirm-trust() {
  local pattern="$1" cmd="$2"
  [[ -z "$pattern" ]] && return 1
  read "reply?总是信任此模式（$pattern），以后不再提示? [y/N] "
  if [[ "$reply" == "y" || "$reply" == "Y" ]]; then
    hlp --trust "$pattern" --example "$cmd" 2>/dev/null \
      && zle -M "已记忆信任（danger.toml 可撤销）"
  fi
}

zle -N hlp-replace
bindkey '^G' hlp-replace
```

**fish（`hlp init fish`）：**

```fish
# hlp fish 集成 —— 在 ~/.config/fish/config.fish 加入：hlp init fish | source
function hlp-replace --description 'hlp: 意图 → 命令'
    # 撤销
    if test -n "$hlp_generated"; and test (commandline) = "$hlp_generated"
        commandline --replace "$hlp_last_intent"
        set -e hlp_generated
        echo "已撤销，恢复意图原文" >&2
        return
    end
    set -l intent (string replace --regex '^//' '' (commandline) | string trim -l)
    if test -z "$intent"
        echo "✗ 意图为空" >&2; return
    end
    echo "… hlp 生成中" >&2
    set -l cmd (hlp --one-line "$intent" 2>/dev/null)
    if test $status -ne 0; or test -z "$cmd"
        echo "✗ 生成失败" >&2; return
    end
    set -l level (hlp --check "$cmd" 2>/dev/null | string match --regex '^level=(.*)$')[2]
    set -l pattern (hlp --check "$cmd" 2>/dev/null | string match --regex '^pattern=(.*)$')[2]
    if test "$level" = "fatal"
        read -p "echo '⚠ 致命命令，需完整重新输入以确认: $cmd
确认输入: '" reply
        if test "$reply" != "$cmd"
            echo "✗ 确认失败，已放弃" >&2; return
        end
        hlp-confirm-trust "$pattern" "$cmd"
    else if test "$level" = "warning"
        read -p "echo '⚠ 警告（'$pattern'），回车采纳 / Ctrl+C 放弃: '"
        hlp-confirm-trust "$pattern" "$cmd"
    end
    set -g hlp_last_intent (commandline)
    set -g hlp_generated "$cmd"
    commandline --replace "$cmd"
    commandline --cursor (string length "$cmd")
end

function hlp-confirm-trust
    set -l pattern $argv[1]
    set -l cmd $argv[2]
    test -z "$pattern"; and return 1
    read -p "echo '总是信任此模式（'$pattern'），以后不再提示? [y/N] '" reply
    if test "$reply" = "y"; or test "$reply" = "Y"
        hlp --trust "$pattern" --example "$cmd" 2>/dev/null; and echo "已记忆信任" >&2
    end
end

bind \cg hlp-replace
```

### 3.4 danger.toml schema

```toml
# ~/.config/hlp/danger.toml —— 危险命令信任列表（hlp --trust 是唯一写者；
# 撤销信任 = 手动删除对应条目）
[[trust]]
pattern = "rm_recursive"            # 内置规则 ID（§3.1 表）
trusted_at = 1793836800             # Unix 秒（决策 6：不引入时间库依赖）
example = "rm -rf ./build"          # 触发时的样例命令，人工审查用
```

校验规则：

- `pattern` 必须是 §3.1 的 8 个 ID 之一，否则加载报错（退出码 3）
- `trusted_at` 为正整数；`example` 为任意字符串（可为空）
- 顶层未知字段 → 报错（与 config.toml 的 deny_unknown_fields 策略一致）
- 文件不存在 → 空 TrustList，合法状态，不创建文件（首次 `--trust` 时创建）

### 3.5 widget ↔ hlp 调用协议（汇总）

| 调用 | 时机 | stdout | 退出码语义 |
|---|---|---|---|
| `hlp --one-line "<intent>"` | Ctrl+G（非撤销态） | top1 命令 | v0.1 契约不变（0/2/3/4/5） |
| `hlp --check "<cmd>"` | 生成成功后立即 | key=value 判定 | 0/3/10/11 |
| `hlp --trust <id> --example "<cmd>"` | 用户选"总是信任" | （空） | 0/3/12 |
| `hlp init <shell>` | 用户配置 shell 时 | 集成脚本全文 | 0/2 |

## 4. 关键流程

### 4.1 Ctrl+G 状态机（三 shell 共用逻辑）

```
按 Ctrl+G
   ↓
BUFFER == hlp_generated 且非空？
   ├─ 是 → 撤销：BUFFER = hlp_last_intent，清空 hlp_generated，提示"已撤销"   [用户确认点 0]
   └─ 否 → 生成路径：
        intent = BUFFER 去掉 "//" 前缀 + 去前导空白；为空 → 提示退出
        提示"… 生成中"
        cmd = $(hlp --one-line "$intent")
        失败/为空 → 提示"✗ 生成失败"，BUFFER 保持意图原文
        verdict = hlp --check "$cmd"
        ├─ level=clean（含 trusted）→ 直接进入替换
        ├─ level=info               → 直接进入替换（轻提示随 reason 可选展示）
        ├─ level=warning            → y/N 确认
        │     ├─ 用户中断（Ctrl+C）→ 放弃，BUFFER 保持意图原文             [用户确认点 1]
        │     └─ 回车 → 询问"总是信任?" → 可选 hlp --trust → 进入替换
        └─ level=fatal              → 要求完整重新输入命令原文
              ├─ 输入不匹配 → 放弃，BUFFER 保持意图原文                    [用户确认点 2]
              └─ 输入匹配   → 询问"总是信任?" → 可选 hlp --trust → 进入替换
   ↓ 替换
hlp_last_intent = 原始整行（含 "//" 前缀）
hlp_generated = cmd
BUFFER = cmd；光标移至末尾
提示"✓ 已生成（再按 Ctrl+G 撤销，回车执行）"
   ↓
用户回车 → shell 原生执行（hlp 全程无 exec，执行权唯一属于用户回车）
```

【用户确认点】共 3 处：撤销本身（0）、warning 的 y/N（1）、fatal 的原文重输（2）。hlp 进程自身在任何路径都不执行命令（§7.3）。

### 4.2 `--check` 内部流程

```
命令字符串
 ↓
load danger.toml → TrustList（失败 → exit 3）
 ↓
按级别序遍历规则（fatal → warning → info），首条命中即返回该级别
   命中且 is_trusted(id) → 折叠为 Clean/trusted=true
   未命中任何规则 → Clean
 ↓
stdout: key=value 行；退出码 0/10/11
```

`rm_recursive_root` / `rm_recursive` 的两步判定（词定位 → 参数区判目标）在 `patterns.rs` 内部完成，对 `check()` 透明。

## 5. 错误分类

v0.1 的 `HlpError` 与退出码 2/3/4/5 全部保留。v0.2 新增：

| 错误场景 | 退出码 | stderr 内容 | 可恢复性 |
|---|---|---|---|
| `init` 的 shell 名非法 / 参数互斥冲突 | 2 | clap 用法说明 | 修正参数 |
| danger.toml 语法/字段非法 | 3 | `hlp: danger.toml 无效：<路径>：<原因>` + 提示手动修复 | 编辑文件 |
| danger.toml 写入失败 | 3 | 同上格式 | 检查权限/磁盘 |
| `--check` 命中 warning | 10 | （stdout 有判定，stderr 无输出） | widget 走确认流 |
| `--check` 命中 fatal | 11 | 同上 | widget 走原文重输流 |
| `--trust` 的 pattern-id 非法 | 12 | 合法 ID 全列表 | 换正确 ID |

退出码段位约定：10/11/12 是 v0.2 新开的"危险判定"段，与 v0.1 的 1~5 段不冲突；`DangerLevel` 到退出码的映射只存在于 `--check` 模式，不污染其他模式。

## 8. 决策与权衡

- **决策 1：危险规则匹配用 `regex` crate，不手写分词器**。8 条规则含词边界、管道上下文、alternation 与排除项（`>>`、`/dev/null`），手写需处理引号嵌套与转义，复杂度与收益不成比例；regex 8 条编译 <1ms，不伤 §1.3 预算。被拒绝的备选：纯手写字符串匹配（`dd` 出现在 `ldd` 这类误报无法廉价排除）。
- **决策 2：危险检测作为独立 `hlp --check` 调用，而非并入 `--one-line` 的 stderr**。① `--one-line` 的 v0.1 契约是"stdout 纯命令 + 退出码集固定"，widget 之外还有 `$(...)` 管道消费者，语义混入会破坏契约稳定性；② `--check` 纯本地 <10ms，widget 两次调用成本可忽略；③ 语义正交：检测只对"生成出来的命令"负责，未来 TUI/Dry-run/语音前端可复用同一 --check。被拒绝的备选：`--one-line` 命中 fatal 时拒绝输出（破坏"退出码 0 拿到命令"的直管道用法，且确认交互无处安放）。
- **决策 3：`--one-line` 行为零改动**。v0.2 的全部安全交互都发生在 shell 集成层（§4.1 状态机），引擎保持纯翻译器。直接管道用法（`$(hlp ...) | sh`）视为用户自担——与 §12"不做命令自动执行"一致：hlp 从不执行，执行的是用户自己的管道。
- **决策 4：集成脚本经 `hlp init <shell>` 输出 + `eval`/`source` 消费，不写用户 rc 文件**。不碰用户配置文件是硬边界（也避免 root/多机路径问题）；`eval "$(hlp init zsh)"` 是 zoxide/starship 等工具的成熟范式。被拒绝的备选：安装时写入 ~/.zshrc（侵入性强、卸载脏）。
- **决策 5：撤销状态用 shell 会话级全局变量（`hlp_generated` / `hlp_last_intent`），不用文件**。撤销 <5ms 预算；跨会话持久化撤销无意义（buffer 本来就是会话内的）。代价：变量名占用全局命名空间，加 `hlp_` 前缀避免冲突。
- **决策 6：`trusted_at` 存 Unix 秒而非 RFC3339 字符串**。避免为一个人工审查字段引入 chrono/time 依赖；审查上下文由 `example` 字段承担（命令原文比时间戳更有用）。被拒绝的备选：chrono（依赖最小化原则，§设计准则）。
- **决策 7：模板中 hlp 调用写裸命令名 `hlp`，不内嵌编译期 exe 绝对路径**。eval 场景下用户 PATH 里的 hlp 与模板属于同一安装；嵌入绝对路径会让 `cargo install --force` 后路径失效。被拒绝的备选：`env!("CARGO_BIN_EXE")` 类绝对路径（开发/安装路径漂移问题）。
- **决策 8：`rm -rf` 按目标分两档（决策表 §3.1）**。REQUIREMENTS §7.1 说 rm -rf "尤其指向 /、~、*" 是致命——"尤其"暗示其余情形较轻。两档（系统级路径 fatal / 普通路径 warning）让 `rm -rf ./build` 这类高频正常操作只走轻确认，避免熔断器因误伤被用户整体关闭。被拒绝的备选：所有 rm -rf 一律 fatal（误伤率高 → 用户直接 `--trust` 或卸载，安全层失效）。
- **决策 9：warning 用"回车采纳/Ctrl+C 放弃"而非 y/N 字母**。终端 read 默认行为下回车=继续最顺手；Ctrl+C 是用户肌肉记忆里最强的"停下"信号。fatal 维持 §7.1 原文：完整重输命令（防手滑的最强摩擦）。
- **决策 10：不提供 `--untrust` 命令**。REQUIREMENTS §7.2 明示信任撤销走"配置文件手动查看和撤销"路线；danger.toml 的条目结构（`[[trust]]` 数组）手动删除即完成撤销，README 说明操作方法。被拒绝的备选：`--untrust` 子命令（超出需求，且维护两套撤销路径不一致）。

## 9. 遗留风险（实现模型最易搞错的点）

1. **regex 误报**：引号内字符串不排除（`echo "curl | sh"` 命中 pipe_to_shell）。实现时必须在代码注释与 README 标注此局限；缓解 = warning/info 不阻塞 + fatal 才需重输 + 信任机制。**严禁**为此提前上"引号感知分词"（那是把 v0.3 的复杂度偷渡进 v0.2）。
2. **zsh 的 `read` 在 ZLE widget 内的行为**：widget 运行于 ZLE 上下文，`read` 交互在部分终端/组合下可能不刷新提示。工单 13 的 DoD 含真机验收 M-6/M-7，若 `read` 不可用，降级方案为 `zle -M` 提示 + 将确认移到 buffer 层（用户手动重输到行内比较）——但必须先实测再降级，不要默认走降级。
3. **`hlp --check` 的 key=value 协议被实现成 JSON 或自由文本**：shell 模板用 `sed -n 's/^level=//p'` 解析，stdout 格式漂移（多 BOM、多空行、键序不定）会静默失效。T-I-12/T-I-16 做字节级断言。
4. **两次 `--check` 调用的浪费**：zsh 模板为解析两个键调用了两次 `hlp --check`。这是模板可读性的刻意取舍（单次调用 + 复杂 shell 解析更易错）；若实现模型顺手"优化"成单次调用，必须同步改三个模板且通过全部手动验收，否则保持原样。
5. **`rm_recursive_root` 的参数区边界**：`rm -rf /; ls` 中 rm 的参数区止于 `;`，判级须只看 rm 段；`foo && rm -rf ~` 要命中。两步判定的单元测试须覆盖分号、`&&`、管道三种边界（T-U-22/29 补充变体）。
