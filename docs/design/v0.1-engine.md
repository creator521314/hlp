# hlp v0.1 引擎设计文档

> 范围：v0.1 引擎 —— 命令行参数 → Provider(ollama) → stdout 单行命令（`--one-line`）；Provider trait 定义
> 唯一需求来源：`docs/REQUIREMENTS.md`（v0.2 草案）。本文档自包含，实现模型无需查看任何聊天记录。
> 版本：v0.1 | 日期：2026-11-04

## 1. 范围与验收标准

### 1.1 本范围内的需求映射

| 需求来源 | 需求内容 | 本设计的落点 | 验收方式 |
|---|---|---|---|
| §3.1 | 自然语言意图作为位置参数输入 | `cli.rs` 位置参数（多词拼接） | 集成测试 T-I-01 |
| §4.1 | `--one-line`：stdout 仅输出一条可执行命令，无装饰；元信息走 stderr | `output.rs` 输出协议 | 集成测试 T-I-02（stdout 纯净性） |
| §4.2 | top1 默认 + 可展开备选（`--alt`）；stderr 提示"还有 N 个备选" | `engine.rs` 候选选择 + `cli.rs --alt` | 集成测试 T-I-03 |
| §6.3 | 插件化 Provider trait（`generate(intent) -> candidates`），ollama 为默认实现 | `provider/mod.rs` + `provider/ollama.rs` | 单元测试 T-U-05 / T-U-06 |
| §6.3 | 配置项 `provider = "ollama"`（默认）于 `~/.config/hlp/config.toml` | `config.rs` | 单元测试 T-U-01~T-U-04 |
| §7.3 | 提示词层面注入安全规则（双保险的提示词那一半） | `prompt.rs` 系统提示词 | 单元测试 T-U-07 |
| §10 v0.1 验收 | `hlp --one-line "列出大文件"` 输出可用命令；stdout 纯净无装饰 | 全链路 | 验收测试 T-I-01 + T-I-02（需本机 ollama 在线） |
| §12 | 不依赖云端 API（默认实现纯本地 ollama） | 默认配置仅指向 `127.0.0.1:11434` | 配置默认值测试 T-U-02 |

### 1.2 明确不在本范围（禁止顺手实现）

- shell 集成（zsh/bash/fish widget）—— v0.2
- 危险命令模式熔断、`danger.toml`、可记忆信任 —— v0.2（v0.1 只做提示词层面的安全约束）
- daemon、unix socket、流式替换 —— v0.3（但 Provider trait 须为流式预留扩展点，见 §8 决策 3）
- 历史缓存、`--clear`、目录豁免 —— v0.3
- tldr 知识库、`hlp -x` 解释模式、Dry-run、TUI —— v0.4

### 1.3 延迟预算（呼应 §6.1）

v0.1 只有 LLM 生成一条路径（缓存与知识库均为后续版本）。本版本的预算份额：

| 环节 | 预算 | 说明 |
|---|---|---|
| 进程启动 + 参数解析 | < 20ms | 禁止引入 tokio 等重运行时（见 §8 决策 1） |
| 配置加载 | < 5ms | 单文件 TOML 读取 |
| LLM 生成 | 1~3s（模型热） | 交给 ollama，本进程只做 HTTP 转发 |
| 端到端（热模型） | < 4s | §6.1 的"感知 < 500ms"依赖 v0.3 daemon + 流式，v0.1 不背此指标 |

## 2. 模块分解

工程结构（均为新建文件，当前仓库仅有骨架 `src/main.rs`）：

```
src/
├── main.rs            # 入口：参数解析 → engine → 退出码映射
├── cli.rs             # clap 参数定义
├── config.rs          # config.toml 加载、默认值、校验
├── engine.rs          # 编排：意图 → Provider → top1 → 输出
├── error.rs           # 错误枚举与退出码
├── output.rs          # stdout/stderr 纯净协议
├── prompt.rs          # 系统提示词构建（含安全规则注入）
└── provider/
    ├── mod.rs         # Provider trait + 请求/响应类型
    └── ollama.rs      # OllamaProvider 实现
```

### 2.1 `cli.rs`

- 【职责】定义并解析命令行参数。
- 【公开接口】

```rust
pub struct CliArgs {
    pub intent: String,        // 位置参数多词以空格拼接后的完整意图
    pub one_line: bool,        // --one-line
    pub alt: bool,             // --alt：展开全部候选
    pub verbose: bool,         // --verbose：元信息到 stderr
}

pub fn parse() -> Result<CliArgs, clap::Error>;
```

- 【参数规格】
  - 位置参数 `<intent...>`：`num_args(1..)`，多词以单个空格拼接。`hlp 列出大文件` 与 `hlp "列出大文件"` 等价。
  - `--one-line`：单行纯净输出。v0.1 中**这是唯一输出形态**，缺省即此行为；显式传 flag 是为了让 shell 集成侧语义明确，并接受缺省（`hlp 列出大文件` 不报错）。
  - `--alt`：展开全部候选（每行一条到 stdout，见 §3.3）。
  - `--verbose`：provider 名、模型名、候选数、耗时（毫秒）输出到 stderr。
- 【依赖】`clap`。
- 【失败语义】缺位置参数、未知 flag → clap 打印用法到 stderr，退出码 2。`-x` 等未来 flag **不预留占位**，由对应版本自行添加。

### 2.2 `config.rs`

- 【职责】加载 `~/.config/hlp/config.toml`，填默认值，校验字段。
- 【公开接口】

```rust
pub struct Config {
    pub provider: String,          // 默认 "ollama"
    pub ollama: OllamaConfig,
}

pub struct OllamaConfig {
    pub base_url: String,          // 默认 "http://127.0.0.1:11434"
    pub model: String,             // 默认 "qwen2.5-coder:3b"
    pub timeout_ms: u64,           // 默认 60000
    pub max_candidates: usize,     // 默认 3
    pub keep_alive: String,        // 默认 "5m"
}

pub fn load() -> Result<Config, HlpError>;
```

- 【加载规则】
  - 配置文件不存在 → 全部使用默认值，**不视为错误**。
  - 配置目录 `~/.config/hlp/` 不存在 → 同上，不创建目录（v0.1 只读不写）。
  - 文件存在但 TOML 语法错误 → 报错退出（退出码 3），stderr 给出文件路径与行号。
- 【校验规则】
  - `provider`：仅接受 `"ollama"`，其他值报错（退出码 3，提示"该 Provider 尚未实现"）。
  - `base_url`：非空字符串；不做连通性预检（见 §8 决策 6）。
  - `timeout_ms`：`1_000..=600_000`，越界报错。
  - `max_candidates`：`1..=10`，越界报错。
  - `model`、`keep_alive`：非空字符串。
- 【依赖】`serde`、`toml`、`dirs`、`crate::error`。
- 【失败语义】一切配置错误均为**直接退出类**（退出码 3），不允许带病运行。

### 2.3 `provider/mod.rs`

- 【职责】定义 Provider 抽象与跨模块流动的请求/响应类型。
- 【公开接口】

```rust
pub struct GenerateRequest {
    pub intent: String,          // 用户原始意图（不做改写）
    pub max_candidates: usize,   // 期望候选数上限
    pub system_prompt: String,   // 由 prompt.rs 构建，Provider 不感知其内容
}

pub struct Candidate {
    pub command: String,         // 一条完整可执行命令，单行，无 Markdown 包裹
}

pub struct GenerateResponse {
    pub candidates: Vec<Candidate>,  // 有序，第 0 个为 top1
}

pub trait Provider {
    fn name(&self) -> &'static str;
    fn generate(&self, req: &GenerateRequest) -> Result<GenerateResponse, HlpError>;
}
```

- 【输入/输出契约】
  - `generate` 返回的候选**可以少于** `max_candidates`（模型给不出那么多时不算错误），但**不允许为空**——空结果由 Provider 转为 `HlpError::NoCandidates`。
  - `Candidate.command` 必须已去除 Markdown 代码围栏、首尾空白与行内换行（多行命令由 Provider 折叠为一行）。清洗责任在 Provider，engine 拿到的即是可直接上屏的最终形态。
- 【依赖】`crate::error`。
- 【失败语义】网络/超时/HTTP 非 2xx → `ProviderError` 类（退出码 4）；响应体无法提取任何候选 → 退出码 5。

### 2.4 `provider/ollama.rs`

- 【职责】`Provider` 的默认实现：调用本地 ollama 的 `POST /api/chat`（非流式）。
- 【公开接口】

```rust
pub struct OllamaProvider { /* 持有 OllamaConfig 与 ureq::Agent */ }

impl OllamaProvider {
    pub fn new(cfg: &OllamaConfig) -> Self;
}

impl Provider for OllamaProvider { /* ... */ }
```

- 【HTTP 契约】
  - 请求：`POST {base_url}/api/chat`，body 字段：`model`、`messages`（system + user 两条）、`stream: false`、`format`（JSON Schema，见 §3.2）、`keep_alive`（取自配置，默认 `"5m"`，让模型在 ollama 侧保温 5 分钟，呼应 §6.2）、`options.temperature: 0.2`（命令生成任务求稳不求活）。
  - 响应：取 `message.content`（字符串，应为符合 schema 的 JSON）。
- 【解析策略（两级）】
  1. 主路径：将 `message.content` 按 JSON 解析为 `{"candidates": ["...", ...]}`。
  2. 兜底路径：JSON 解析失败时，按行切分 `content`，逐行剥离 Markdown 围栏（```` ``` ````）、行首序号（`1.`/`-`）、反引号包裹，取非空且"看起来像命令"的行作为候选。"看起来像命令"的判定：不含中文句号结尾、不以解释性前缀（"这条命令""该命令""输出"等）开头。兜底命中的候选数若为 0 → `HlpError::NoCandidates`。
- 【清洗】每个候选：去首尾空白 → 折叠内部换行为单空格 → 剥离 ```` ```bash ```` 类围栏。
- 【超时】整体请求超时 = `config.timeout_ms`（默认 60s，覆盖 ollama 冷加载模型的场景）。
- 【依赖】`ureq`、`serde`、`serde_json`、`crate::config`、`crate::error`。
- 【失败语义】连接被拒绝 / DNS / 超时 → `HlpError::ProviderUnreachable`（stderr 附带"请确认 ollama 已启动：ollama serve"提示）；HTTP 404 → 提示模型可能未拉取（`ollama pull <model>`）；其他 HTTP 非 2xx → `HlpError::ProviderHttp`。

### 2.5 `prompt.rs`

- 【职责】构建发送给 LLM 的系统提示词，注入输出契约与安全规则（§7.3 的提示词那一半）。
- 【公开接口】

```rust
pub fn build_system_prompt(max_candidates: usize) -> String;
```

- 【提示词必须包含的规则（实现时逐条落实，措辞可微调）】
  1. 角色：将自然语言意图翻译为单行 Linux shell 命令。
  2. 输出契约：只输出 JSON `{"candidates": [...]}`，候选数 ≤ `max_candidates`，按推荐度降序；每条命令单行、不含 Markdown、不含解释文字。
  3. 安全规则：对于意图本身以破坏为目的（清空磁盘、破坏系统、无差别删除），返回空候选数组 `{"candidates": []}`，不得生成。**注意**：用户明确要求的含破坏性参数的命令（如"删除 ./tmp 目录"→ `rm -rf ./tmp`）属于正常翻译，必须生成——安全熔断是 v0.2 输出层的职责，提示词层只拦"恶意意图"，不拦"危险命令"。
  4. 平台约定：目标环境为 Linux + 常见 GNU 工具链。
- 【失败语义】纯函数，无失败路径。
- 【依赖】无。

### 2.6 `engine.rs`

- 【职责】编排主流程：组装请求 → 调 Provider → 选 top1 → 交给 output。
- 【公开接口】

```rust
pub struct Engine { /* 持有 Config + Box<dyn Provider> */ }

impl Engine {
    pub fn from_config(cfg: Config) -> Result<Self, HlpError>;
    pub fn run(&self, args: &CliArgs) -> Result<EngineOutcome, HlpError>;
}

pub struct EngineOutcome {
    pub top1: String,               // 选中命令
    pub alternatives: Vec<String>,  // 其余候选（可能为空）
    pub provider_name: &'static str,
    pub model: String,
    pub elapsed: Duration,
}
```

- 【行为契约】
  - top1 = `candidates[0]`（Provider 已保证有序、非空）。
  - 候选总数 > 1 时，在 `EngineOutcome` 中保留备选数量，供 output 打印"还有 N 个备选（`hlp --alt` 查看）"到 stderr（呼应 §4.2）。
  - engine 自身**不打印任何字符**，输出全部委托 `output.rs`（保证纯净协议只有一个守门人）。
- 【依赖】`provider`、`prompt`、`config`、`cli`、`error`。
- 【失败语义】透传 Provider 错误，不吞不包。

### 2.7 `output.rs`

- 【职责】§4.1 纯净输出协议的唯一落地处。
- 【公开接口】

```rust
pub fn emit(outcome: &EngineOutcome, args: &CliArgs) -> ();
```

- 【协议规则（硬约束）】
  - **stdout**：默认模式有且仅有一行——top1 命令原文 + `\n`，无前后空白、无装饰字符、无 ANSI 转义。`--alt` 模式下 stdout 输出全部候选，每行一条（仍是纯命令，无序号装饰），第一行为 top1。
  - **stderr**：备选数量提示、`--verbose` 元信息（provider / model / 候选数 / 耗时毫秒）、一切错误信息。
  - 任何模块禁止绕过本模块直接 `println!` 到 stdout（main.rs 的调试残留也要清除）。代码评审与测试 T-I-02 共同保证。
- 【失败语义】写 stdout 失败（如管道断裂 EPIPE）→ 静默退出码 0，不报错（下游 `head` 截断属正常用法）。

### 2.8 `main.rs`

- 【职责】最薄入口：`cli::parse` → `config::load` → `Engine::from_config` → `engine.run` → `output::emit`；错误映射为退出码（§5）。
- 【失败语义】所有 `HlpError` 在此统一打印到 stderr（格式：`hlp: <错误描述>`）并以对应退出码退出。

## 3. 数据结构与协议

### 3.1 配置文件 schema：`~/.config/hlp/config.toml`

```toml
provider = "ollama"        # 默认 "ollama"；其他值报错（预留扩展）

[ollama]
base_url = "http://127.0.0.1:11434"  # 默认本地；允许指向局域网 ollama
model = "qwen2.5-coder:3b"           # [假设] 默认 3b（§6.2 给出 1.5b/3b 两个选项，取较大者保质量）
timeout_ms = 60000                   # [假设] 默认 60s，覆盖模型冷加载；校验区间 1s~600s
max_candidates = 3                   # [假设]（§14 开放问题：候选上限未定，取 3）
keep_alive = "5m"                    # 透传 ollama；默认保温 5 分钟
```

校验规则见 §2.2。`danger.toml` 属于 v0.2，本版本**不读取不创建**。

### 3.2 LLM 输出 schema（透传给 ollama `format` 字段的 JSON Schema）

```json
{
  "type": "object",
  "properties": {
    "candidates": {
      "type": "array",
      "items": { "type": "string" },
      "maxItems": 10
    }
  },
  "required": ["candidates"]
}
```

小模型对 schema 的遵从度不完全可靠，因此 §2.4 的兜底解析路径是必须实现的，不是可选项。

### 3.3 stdout/stderr 协议（§4.1 落地）

| 场景 | stdout | stderr | 退出码 |
|---|---|---|---|
| 正常，单候选 | `<命令>\n` | （--verbose 时有元信息） | 0 |
| 正常，多候选 | `<top1 命令>\n` | `还有 N 个备选（hlp --alt 查看）` | 0 |
| `--alt`，多候选 | 每行一条候选，共 N+1 行 | 同上提示可省略 | 0 |
| 用法错误 | （空） | clap 用法说明 | 2 |
| 配置错误 | （空） | `hlp: <错误>（文件路径:行号）` | 3 |
| Provider 不可达/超时 | （空） | `hlp: <错误> 提示：请确认 ollama 已启动...` | 4 |
| 响应无可用候选 | （空） | `hlp: <错误>` | 5 |

保证：`$(hlp --one-line ...)` 在退出码 0 时拿到的永远是且只是一条命令。

## 4. 关键流程

### 4.1 主流程（v0.1 唯一流程）

```
argv
 ↓
cli::parse() ──失败──→ stderr 用法说明, exit 2
 ↓ CliArgs
config::load() ──失败──→ stderr 配置错误, exit 3
 ↓ Config（文件缺失则全默认）
prompt::build_system_prompt(max_candidates)
 ↓ system_prompt
Engine::from_config(cfg)          # 按 cfg.provider 构造 OllamaProvider
 ↓
engine.run(args)
 ├── 组装 GenerateRequest { intent, max_candidates, system_prompt }
 ├── provider.generate(req) ──网络/HTTP 错──→ exit 4
 │                        └─无候选/解析失败──→ exit 5
 └── EngineOutcome { top1, alternatives, ... }
 ↓
output::emit()
 ├── stdout: top1（或 --alt 全部候选）
 └── stderr: 备选提示 / verbose 元信息
 ↓
exit 0
```

【用户确认点】v0.1 不存在任何命令执行路径：本进程的唯一副作用是向 stdout 写字符串。执行确认点位于 v0.2 的 shell 集成层（用户回车），不在本范围。

### 4.2 响应解析流程（Provider 内部）

```
message.content
 ↓
尝试 JSON.parse → {"candidates": [...]}
 ├── 成功 → 逐条清洗（去围栏/折叠换行/去空白）
 │          ├── 清洗后非空 → GenerateResponse
 │          └── 全空 → HlpError::NoCandidates (exit 5)
 └── 失败 → 兜底：按行切分 → 剥离围栏/序号/反引号
            → 过滤非命令行（解释性前缀、句号结尾）
            ├── 有剩余 → 清洗 → GenerateResponse
            └── 无剩余 → HlpError::NoCandidates (exit 5)
```

## 5. 错误分类

```rust
pub enum HlpError {
    // —— 直接退出类：用户必须介入修复 ——
    ConfigInvalid { path: PathBuf, reason: String },   // exit 3
    ConfigIo { path: PathBuf, source: io::Error },     // exit 3（存在但不可读）

    // —— Provider 类：环境/服务问题 ——
    ProviderUnreachable { base_url: String, reason: String }, // exit 4（含超时）
    ProviderHttp { status: u16, body_excerpt: String },       // exit 4

    // —— 响应质量类：服务正常但没给出可用结果 ——
    NoCandidates { raw_excerpt: String },              // exit 5（stderr 附原始响应片段便于调试）
}
```

| 错误 | 类别 | 退出码 | 可恢复性 |
|---|---|---|---|
| clap 用法错误 | 用法 | 2 | 用户修正参数 |
| ConfigInvalid / ConfigIo | 配置 | 3 | 用户修配置文件 |
| ProviderUnreachable | 环境 | 4 | 启动 ollama 后重试 |
| ProviderHttp | 环境 | 4 | 404 时提示 `ollama pull` |
| NoCandidates | 质量 | 5 | 换措辞重试 / 换模型 |
| 其他内部错误（兜底） | 内部 | 1 | 视为 bug |

设计约束：错误信息面向终端用户，必须给出**下一步动作提示**（如"请确认 ollama 已启动"），不打印 Rust 调试结构。

## 6. 测试计划

### 6.1 单元测试

| 编号 | 模块 | 【前提】 | 【动作】 | 【断言】 |

## 8. 决策与权衡

- **决策 1：HTTP 客户端选 `ureq` 而非 `reqwest`**。v0.1 只需要阻塞式 POST 一个 JSON，reqwest 会拖入 tokio 运行时，显著拖慢进程冷启动（违背 §1.3 的 < 20ms 启动预算）且增大二进制。ureq 阻塞、零运行时、够用。被拒绝的备选：reqwest（重）、hyper（更底层，无收益）。v0.3 流式若需逐行读响应体，ureq 返回的 `impl Read` 同样支持按行读取 NDJSON，届时验证后再决定是否更换。
- **决策 2：v0.1 走非流式 `/api/chat`（`stream: false`）**。流式替换的价值依赖 v0.2 shell 集成 + v0.3 daemon 才能被用户感知；v0.1 是管道消费形态（`$(hlp ...)`），流式无意义且徒增解析复杂度。被拒绝的备选：v0.1 即流式到 stdout——shell 命令替换场景下换行会污染结果。
- **决策 3：Provider trait 只定义同步 `generate`，流式以"新增带默认实现的方法"方式在 v0.3 扩展**（如 `generate_stream`，默认实现委托 `generate`）。trait 上加默认方法是向后兼容演进，v0.1 不必为未实现的需求预留复杂泛型。被拒绝的备选：现在就定义 `Stream` 关联类型——为想象中的需求付复杂度税。
- **决策 4：LLM 输出契约用 JSON Schema（ollama `format` 字段）+ 行解析兜底，而非纯提示词约束**。qwen2.5-coder:1.5b/3b 量级的小模型对格式指令的遵从度不稳定，schema 强约束 + 兜底解析双保险。被拒绝的备选：纯提示词约束（实测不可靠）；只解析 JSON 不做兜底（小模型违约时直接死，体验差）。
- **决策 5：危险命令模式熔断整体留在 v0.2，v0.1 只做提示词层"恶意意图返回空候选"**。§10 明确把危险检测划给 v0.2；v0.1 若提前做模式匹配，会与 v0.2 的可记忆信任机制（danger.toml）产生两套不一致的实现。提示词层只拦"以破坏为目的的意图"，绝不拦"用户明确要求的危险命令"——后者是翻译器的本职，拦截权属于输出确认层。
- **决策 6：启动时不做 ollama 连通性预检**。预检会白付一次 HTTP 往返（缓存命中路径的未来预算只有 10ms）；连通性问题在真正调用失败时以错误信息+行动提示呈现即可。被拒绝的备选：每次启动 GET /api/tags 预检。
- **决策 7：CLI 解析用 `clap`（derive）**。手写 `std::env::args` 解析在多 flag + 变长位置参数 + 自动用法说明场景下错误处理成本高于一个成熟依赖；clap 是 Rust CLI 事实标准。被拒绝的备选：手写解析（易错）、pico-args（用法说明需手写）。
- **决策 8：配置目录用 `dirs` 而非手写 `~/.config` 拼接**。手写无法正确处理 `XDG_CONFIG_HOME` 覆盖场景；dirs 是单职责小 crate。被拒绝的备选：`std::env::home_dir` 手工拼（XDG 语义错）。
- **决策 9：默认模型 `qwen2.5-coder:3b`**。[假设]（§14 未定点）§6.2 给出 1.5b/3b 两档，取 3b：v0.1 无缓存兜底，生成质量优先于速度；用户可在 config.toml 降到 1.5b。
- **决策 10：`--alt` 的候选展开到 stdout 而非 stderr**。展开候选是"主要产出物"而非"元信息"，用户可能需要 `| fzf` 等管道消费；stderr 无法被管道捕获。被拒绝的备选：候选进 stderr（不可管道化）。

## 9. 遗留风险（实现模型最易搞错的点）

1. **stdout 纯净性被无意破坏**：任何一处调试 `println!`、panic 打到 stdout、或 `--verbose` 元信息走错流，都会污染 `$(hlp ...)` 的命令替换结果。stdout 的唯一写入者是 `output.rs`；T-I-02 用字节级断言守门。
2. **两级解析只做一级**：小模型不保证输出合法 JSON，跳过兜底解析会导致大量本可成功的请求以退出码 5 失败。兜底解析（§4.2）是必须实现项。
3. **提示词安全规则误伤正常翻译**：把"生成危险命令"和"恶意意图"混为一谈，导致 `rm -rf ./tmp` 这类正常请求被模型拒绝（返回空候选）。规则措辞必须区分二者（§2.5 第 3 条）；T-I-08 是回归守门。
4. **timeout 设太短**：ollama 首次调用需把模型加载进内存，冷启动可达 10~30s。默认 60s 是刻意放宽的，实现者不要"优化"成 5s。
5. **意图位置参数的拼接**：`hlp 把 文件 列出来`（用户不加引号）是合法输入，必须用空格拼接全部位置参数，而不是只取第一个或报错——但拼接时不得引入多余空格/换行，原样性影响生成质量与 T-I-02 的字节断言。
