# hlp v0.3 daemon 与历史缓存设计文档

> 范围：v0.3 —— 常驻 daemon（按需拉起 + 空闲 5 分钟超时退出）+ unix socket + 流式替换；历史缓存（默认开启 + `hlp --clear` + 目录级豁免）
> 唯一需求来源：`docs/REQUIREMENTS.md`（v0.2 草案），§13 决策记录优先级最高。本文档自包含，实现模型无需查看任何聊天记录。

> 版本：v0.3 | 日期：2026-11-04

### 2.1 `daemon/protocol.rs`

- 【职责】定义 socket 协议类型与版本（NDJSON：每行一个 JSON 对象）。
- 【公开接口】

```rust
pub const PROTOCOL_VERSION: u32 = 1;

/// 客户端 → daemon，单行 JSON
pub struct Request {           // serde(tag = "op")
    pub v: u32,                // = PROTOCOL_VERSION；不匹配 → daemon 回 error，客户端回退直连
    pub op: Op,
}
pub enum Op {
    Generate { intent: String, max_candidates: usize, cwd: PathBuf, stream: bool },
    Learn { intent: String, command: String, cwd: PathBuf },
    Clear,
    Ping,
}

/// daemon → 客户端，每行一个
pub enum Event {               // serde(tag = "type")
    Chunk { text: String },        // 当前最优候选快照（流式模式才产生）
    Done { candidates: Vec<String>, source: Source },  // source: cache | llm
    Ok,                            // Learn/Clear/Ping 的应答
    Error { kind: ErrorKind, message: String },        // kind: provider_unreachable | no_candidates | protocol
}
```

- 【契约】
  - 连接建立后客户端**先发一行 Request**，daemon 回零或多行 Event，以 `Done`/`Ok`/`Error` 之一终结并关闭连接。
  - `Chunk.text` 是**全量快照**（非增量 delta），消费方直接整体替换 buffer；快照经过 v0.1 的候选清洗（围栏/换行折叠）。
  - `Error.kind = protocol` 用于版本不匹配。
- 【失败语义】协议解析失败 → daemon 回 `Error{protocol}` 并断连；客户端收到任何协议异常 → 回退直连路径（决策 5）。

### 2.2 `daemon/server.rs`

- 【职责】daemon 主进程逻辑：监听 unix socket、串行处理请求、空闲超时退出。
- 【公开接口】

```rust
/// daemon 主循环（由 `hlp daemon` 子命令调用，阻塞至退出）
pub fn serve(cfg: &Config) -> Result<(), HlpError>;
```

- 【行为契约】
  - socket 路径：`config.daemon.socket_path` 非空则用之；否则 `$XDG_RUNTIME_DIR/hlp.sock`，XDG_RUNTIME_DIR 缺失时 `/tmp/hlp-{uid}.sock`。bind 前 `chmod 0700` 父目录 / socket 文件 `0600`。
  - **串行 accept**：一次只处理一个连接（决策 4）。listener 设 nonblocking，100ms 轮询间隔内检查空闲计时。
  - **空闲退出**：每次请求处理完重置计时；连续 `idle_secs`（默认 300s）无请求 → 清理 socket 文件并退出码 0。
  - 请求处理：`Generate` → 先查缓存（命中 → `Done{source:cache}`，不碰 LLM）→ 未命中走 Provider（stream 请求逐 chunk 转发快照）→ 成功后**不落缓存**（学习由 Learn 显式触发，见决策 6）。
  - `Learn` → cache.learn（豁免目录下静默丢弃，回 `Ok`）；`Clear` → cache.clear；`Ping` → `Ok`（供健康检查）。
- 【依赖】`std::os::unix::net`、`cache`、`provider`、`config`。
- 【失败语义】serve 启动失败（socket 被占且对端存活 → 说明已有 daemon，直接退出码 0 让位于现存实例；被占但对端死 → 删文件重 bind）。运行期单请求出错 → 回 Error 事件，不退出主循环。

### 2.3 `daemon/mod.rs`（拉起与路径）

- 【公开接口】

```rust
/// 确保 daemon 存活：socket 可连且 Ping 通 → 直接返回；否则拉起。
/// 返回 Err 表示拉起失败，调用方回退直连。
pub fn ensure_running(cfg: &Config) -> Result<(), HlpError>;

pub fn socket_path(cfg: &Config) -> PathBuf;
```

- 【拉起流程（§4.1）】用 `fs2` flock 锁 `~/.cache/hlp/daemon.lock` 防并发双拉起；锁内二次检查 socket；拉起方式为 spawn 自身 `hlp daemon`（`std::process::Command`，stdout/stderr 重定向到 `~/.cache/hlp/daemon.log`，`setsid` 脱离会话——用 `pre_exec` 调 `libc::setsid`？不行，禁止裸 libc…… 见决策 8：用 `Command::new(current_exe).arg("daemon").stdin(null).stdout(file).stderr(file)` + 立即返回，不 setsid——widget 场景下 hlp 由 shell spawn，daemon 随终端会话共生死是可接受的，决策 8 有完整权衡）。
- 【等待就绪】拉起后轮询 socket 连通（10ms × 100 次 = 1s 上限）。

### 2.5 `cache/store.rs`

- 【职责】SQLite 存取（rusqlite，bundled 静态编译，决策 9）。
- 【DB 路径】`dirs::data_dir()/hlp/hlp.sqlite`（即 `~/.local/share/hlp/hlp.sqlite`）。
- 【schema（user_version = 1）】

```sql
CREATE TABLE IF NOT EXISTS entries (
  id            INTEGER PRIMARY KEY,
  intent_norm   TEXT NOT NULL,        -- 归一化后的意图（索引列）
  intent_raw    TEXT NOT NULL,        -- 原始意图（展示/调试）
  command       TEXT NOT NULL,        -- 最终采纳/修正后的命令
  source        TEXT NOT NULL,        -- 'adopted' | 'correction'
  hits          INTEGER NOT NULL DEFAULT 0,
  created_at    INTEGER NOT NULL,     -- Unix 秒
  last_used_at  INTEGER NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_intent_norm ON entries(intent_norm);
```

- 【公开接口】

```rust
pub struct Store { /* rusqlite::Connection（WAL + busy_timeout 5s）*/ }
pub struct Entry { pub intent_raw: String, pub command: String, pub source: Source, pub hits: u32 }

impl Store {
    pub fn open(path: &Path) -> Result<Store, HlpError>;
    /// 精确命中：同一归一化意图取 last_used_at 最新的一条
    pub fn exact(&self, intent_norm: &str) -> Result<Option<Entry>, HlpError>;
    /// 前缀命中：intent_norm 以某条已存意图开头（长度 ≥ 4 字符才参与），最长前缀优先
    pub fn prefix(&self, intent_norm: &str) -> Result<Option<Entry>, HlpError>;
    /// 学习写入：同 (intent_norm) 已存在 → 更新 command/source、hits+1、last_used_at；
    /// 不存在 → 插入
    pub fn learn(&mut self, intent_raw: &str, command: &str, source: Source) -> Result<(), HlpError>;
    pub fn clear(&mut self) -> Result<(), HlpError>;   // DELETE FROM entries（保留表结构）
    pub fn touch(&mut self, intent_norm: &str) -> Result<(), HlpError>; // 命中时 hits+1
}
```

- 【失败语义】DB 打开/读写失败 → `HlpError::CacheUnavailable`（新增，退出码 6）——但**调用方一律降级继续**（缓存是加速器不是硬依赖，见决策 3）。

### 2.8 `provider` 流式扩展（v0.1 决策 3 的兑现）

- 【trait 扩展（向后兼容）】

```rust
pub trait Provider {
    fn name(&self) -> &'static str;
    fn generate(&self, req: &GenerateRequest) -> Result<GenerateResponse, HlpError>;

    /// 流式生成：on_chunk 逐次收到"当前最优候选快照"（全量替换语义）。
    /// 默认实现：退化为同步 generate，完成后一次性回调 top1。
    fn generate_stream(&self, req: &GenerateRequest, on_chunk: &mut dyn FnMut(&str))
        -> Result<GenerateResponse, HlpError> { /* default: self.generate(req) + 回调一次 */ }
}
```

- 【ollama 流式实现】`stream: true`，`ureq` 响应 `into_reader()` 按行读 NDJSON：`{"message":{"content":"..."},"done":false}`。累计 content，用**增量解析器**提取 `candidates[0]` 的部分值（§4.3），每个 chunk 清洗后回调快照；`done:true` 后用 v0.1 的两级解析产最终候选集。
- 【失败语义】流中途断连 → `ProviderUnreachable`，已发出的快照由调用方决定保留或回滚（widget 回滚到意图原文，§4.4）。

### 2.9 `cli.rs` / `main.rs`（修改）

- 【新增参数】
  - `--stream`：与 `--one-line` 同义但逐快照输出（stdout 每行一个全量快照，最后一行为最终 top1）。与 `--alt` 互斥。
  - `--clear`：清空历史缓存，退出 0。与生成参数互斥。
  - `hlp daemon`：daemon 主循环（文档标注为内部子命令，用户也可手动拉起）。
  - `hlp cache-learn --intent "<意图>" --command "<命令>" [--cwd <路径>]`：学习回流（preexec 钩子调用），本地操作、不走 LLM、不拉起 daemon（daemon 不在则直接写 DB）。
- 【分发】`--clear` / `cache-learn` 为本地路径；`--one-line` / `--stream` 走 daemon-first 引擎路径（§4.2）。

### 2.10 `engine.rs`（修改）

- 【run 流程变更】

```
意图归一化 → 缓存 lookup
  ├─ 命中 → 单候选返回（source=cache，verbose 标注）
  └─ 未命中 → daemon-first：
        ensure_running 成功 → daemon::client::generate（stream 时接快照回调）
        失败（拉起失败/协议错误）→ 回退 v0.1 直连 Provider 路径
```

- 【契约保持】stdout 纯净协议、退出码集不变；`EngineOutcome` 增加 `source: Source` 字段。

## 3. 数据结构与协议

### 3.1 config.toml 新增两节（默认值 + 校验）

```toml
[cache]
enabled = true            # §8 默认开启
exempt_dirs = ["~/secrets"]  # 目录豁免列表（词法前缀；~ 加载时展开为 $HOME）

[daemon]
idle_secs = 300           # 空闲超时（§6.2 决策：5 分钟）；校验 10..=3600
socket_path = ""          # 空 = 自动（$XDG_RUNTIME_DIR/hlp.sock 或 /tmp/hlp-{uid}.sock）
```

校验规则：`idle_secs` 越界 / `socket_path` 为相对路径 → ConfigInvalid（退出码 3）。`exempt_dirs` 条目为空串 → 报错。未知字段仍 deny。

### 3.2 socket 协议帧样例

请求（单行）：
```json
{"v":1,"op":"generate","intent":"列出大文件","max_candidates":3,"cwd":"/home/x","stream":true}
```

流式响应（多行）：
```json
{"type":"chunk","text":"find . -ty"}
{"type":"chunk","text":"find . -type f -size +100M"}
{"type":"done","candidates":["find . -type f -size +100M"],"source":"llm"}
```

缓存命中响应（单行终结）：
```json
{"type":"done","candidates":["find . -type f -size +100M"],"source":"cache"}
```

错误：
```json
{"type":"error","kind":"provider_unreachable","message":"..."}
```

### 3.3 `--stream` 的 stdout 协议

每行一个**全量快照**（可直接整体替换 shell buffer），最后一行是最终 top1。缓存命中时恰好一行。stderr 协议与 v0.1 一致（备选提示/verbose 元信息）。`--stream` 退出码集 = v0.1 的 0/2/3/4/5 + 缓存不可用不报错（降级）。

### 3.4 文件布局

| 路径 | 内容 | 权限 |
|---|---|---|
| `$XDG_RUNTIME_DIR/hlp.sock` 或 `/tmp/hlp-{uid}.sock` | daemon socket | 0600 |
| `~/.cache/hlp/daemon.lock` | 拉起互斥锁（fs2 flock） | 0600 |
| `~/.cache/hlp/daemon.log` | daemon stderr 重定向 | 0644 |
| `~/.local/share/hlp/hlp.sqlite` | 缓存 DB（WAL） | 0600 |

## 4. 关键流程

### 4.1 daemon 按需拉起（含防并发）

```
需要 daemon（--one-line / --stream 且缓存未命中时）
 ↓
socket 存在且 Ping 通？ ──是──→ 直接用
 ↓ 否
打开 ~/.cache/hlp/daemon.lock，fs2 flock（阻塞等锁 ≤2s，超时 → 回退直连）
 ↓ 持锁后二次检查 socket（可能已被竞争者拉起）
spawn: current_exe daemon（stdin null，stdout/stderr → daemon.log）
 ↓
轮询 Ping（10ms × 100）
 ├─ 通 → 释放锁，使用
 └─ 1s 超时 → 释放锁，回退直连（stderr verbose 注记）
```

### 4.2 生成主流程（daemon 热路径）

```
widget: Ctrl+G
 ↓
hlp --stream "$intent"
 ├── 缓存 lookup（归一化 → exact → prefix）
 │    └─ 命中 → stdout 单行快照，done(source=cache)
 └── 未命中 → ensure_running → socket 请求 stream=true
        ├── daemon 内 Provider.generate_stream
        │     每个 LLM chunk → 增量解析 → 快照行到 stdout
        └── done → 最终 top1 行
 ↓ 任何 daemon 路径失败
回退 v0.1 直连（同步 generate，一次性快照）
```

### 4.3 流式增量解析器（daemon/Provider 内部）

```
accumulated = ""
对每个 NDJSON 行 {"message":{"content": c}}:
    accumulated += c
    snapshot = try_extract_first_candidate(accumulated)
    if snapshot 变化且非空: 清洗 → on_chunk(snapshot)

try_extract_first_candidate(acc):
    定位 `"candidates"` → 其后第一个 `[` → 其后第一个 `"`
    从该引号后扫描到第一个未转义的 `"`
      - 未找到闭合引号 → 返回当前部分串（末尾悬挂的 `\` 丢弃）
      - 找到 → 返回完整串
    沿途处理 \\ \" \n 转义
    定位失败（模型还没吐到数组）→ None
```

done 后：完整 content 走 v0.1 两级解析（JSON → 行兜底）产最终候选集，与最后一个快照无关。

### 4.4 流式 widget 更新（集成模板 v2，zsh 为例）

```zsh
hlp-replace() {
  # 撤销分支与 v0.2 相同，略
  local intent=...
  zle -M "… hlp 生成中"; zle reset-prompt
  local last="" final="" rc
  while IFS= read -r line; do
    last="$line"
    BUFFER="$line"; CURSOR=${#BUFFER}
    zle reset-prompt          # 每快照刷新 → "命令正在打字"
  done < <(hlp --stream "$intent" 2>/dev/null)
  rc=$?    # 注意：进程替换拿不到退出码，用 PIPESTATUS/临时文件传递（实现细节，见遗留风险 #2）
  if [[ -z "$last" ]]; then zle -M "✗ 生成失败"; return; fi
  # 危险检查（v0.2 契约不变：hlp --check "$last"）→ 确认流 → 替换
}
```

bash / fish 模板同理（`while read` + READLINE_LINE / commandline --replace），全文规格在实现工单 #23 中按 v0.2 模板升级——**v2 模板与 v0.2 模板并存交付**（`hlp init zsh` 输出 v2），用户重新 eval 即升级。

bash: trap DEBUG（决策 7，侵入性已记录）

hlp-preexec(executed_line):
  if [[ -z "$hlp_generated" ]]; return          # 非 hlp 来源，不学
  if executed == "$hlp_generated":
      hlp cache-learn --intent "$hlp_last_intent" --command "$executed"   # source=adopted

## 8. 决策与权衡

- **决策 1：daemon 用 unix socket + NDJSON 行协议，不用 HTTP/gRPC**。本机单用户场景，unix socket 零网络栈开销、权限天然随文件系统；NDJSON 每行一帧天然契合流式。被拒绝的备选：HTTP on localhost（端口占用/权限问题）、protobuf（杀鸡用牛刀）。
- **决策 2：缓存匹配 v0.3 只做"精确 + 前缀"两级（§14 开放问题的解答，[假设]）**。模糊匹配需要相似度阈值实验与误命中评估，且 tldr 层（v0.4）上线后匹配责任会重新分层；前缀匹配已覆盖"意图越写越细"的主流修正模式。被拒绝的备选：v0.3 即上编辑距离（无阈值依据，误命中比未命中更伤信任）。
- **决策 3：缓存是加速器不是硬依赖——一切缓存故障静默降级**。`lookup` 失败返回 None、`learn` 失败丢弃；只有用户显式操作（`--clear`、`cache-learn`）失败才报退出码 6。被拒绝的备选：缓存故障阻断生成（违背"翻译器"本职）。
- **决策 4：daemon 串行 accept，一次处理一个请求**。hlp 的使用模式（人按 Ctrl+G）本质串行；并发收益为零而复杂度（连接线程池/SQLite 并发）非零。被拒绝的备选：每连接一线程（WAL 下可行但无需求）。
- **决策 5：daemon 路径任何失败一律回退 v0.1 直连路径**。daemon 是性能优化层，正确性由直连路径兜底——这与决策 3 同构，保证 v0.3 的全部新基础设施都不在关键路径的正确性上。被拒绝的备选：daemon 失败即报错（用户视角莫名变差）。
- **决策 6：生成成功不自动落缓存，学习只经 cache-learn（preexec）显式触发**。只有"用户回车执行了"才算采纳信号；生成即落缓存会把未被采纳的坏结果变成高优先级缓存。被拒绝的备选：生成时落缓存 + hits 权重（坏命令一旦入缓存会反复置顶）。
- **决策 7：bash 的学习回流用 DEBUG trap（唯一可行方案）**。bash 无 preexec；`trap '...' DEBUG` 会在每条命令前触发，需配合 `$hlp_generated` 门控（只处理 hlp 生成的行）+ `PROMPT_COMMAND` 防重复。已知侵入性写入 README 与遗留风险 #3。被拒绝的备选：解析 history（`history 1` 时机不可靠）；引入 bash-preexec 外部依赖（违背"薄集成"原则）。
- **决策 8：daemon 用 `Command::new(current_exe).arg("daemon")` spawn，不做 double-fork/setsid 守护化**。setsid 需要 libc/nix 新依赖；而 widget 场景下 hlp 由交互 shell spawn，daemon 随终端会话共生死与"空闲 5 分钟退出"语义不冲突（§6.2 本来就不要求常驻）。被拒绝的备选：nix::setsid 完整守护化（为一个 5 分钟就退出的进程引入 nix 不值）。
- **决策 9：rusqlite 用 bundled feature（静态编译 SQLite）**。避免目标机缺 libsqlite3 或版本漂移；编译时间增加一次性成本，运行时零外部依赖，符合单二进制分发（§9）。被拒绝的备选：链接系统 sqlite（AUR/跨发行版分发时翻车）。
- **决策 10：豁免目录用词法前缀匹配（~ 展开 + 绝对化），不做 canonicalize**。canonicalize 要求路径存在且解析符号链接，开销与边界 case（目录被删、链接变化）不值；词法前缀的局限（symlink 绕过）写入遗留风险。被拒绝的备选：canonicalize + symlink 解析。

## 9. 遗留风险（实现模型最易搞错的点）

1. **增量解析器的转义边界**：chunk 恰好在 `\"` 的反斜杠处断开时，悬挂反斜杠必须丢弃而非透传，否则快照会闪烁出非法字符；T-U-49 是守门测试，实现者若跳过转义处理会直接栽在这里。
2. **zsh 进程替换拿不到 hlp 退出码**：`< <(...)` 的进程替换不向 `$?` 传值。实现者必须在模板里用 `{ hlp --stream ...; echo "rc=$?" >&3; } 3>tmpfile` 或 `PIPESTATUS` 等价物传递退出码——模板全文写进代码前，先用最小脚本在 zsh 实测该传码手法，三种 shell 各验证一次。
3. **bash DEBUG trap 的双重触发与嵌套**：DEBUG trap 对复合命令（管道每段）都会触发，且 `cache-learn` 自身也会触发 trap → 必须门控：`$hlp_generated` 非空才处理，处理完立即 unset；并在 trap 内首行判 `$BASH_COMMAND` 是否为 `hlp cache-learn*` 直接跳过，防自激。
4. **SQLite 并发**：daemon 与 `cache-learn` 直连 DB 可能同时写——Store 打开时必须 `PRAGMA journal_mode=WAL` + `busy_timeout=5000`，缺 busy_timeout 会在并发下抛 database is locked。
5. **daemon 让位语义**：第二个 `hlp daemon` 发现 socket 已被存活实例占用时，应退出码 **0**（让位）而非报错——实现者容易顺手写成错误退出，导致 ensure_running 误判拉起失败并回退直连，daemon 永远起不来。T-I-20 覆盖此点。
