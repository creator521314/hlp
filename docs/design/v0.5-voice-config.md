## 1. 范围与验收标准

### 1.1 需求映射

| 需求来源 | 需求内容 | 本设计的落点 | 验收方式 |
|---|---|---|---|
| §3.4 | 语音输入：whisper.cpp 本地转写（GGUF，CPU 可跑） | `voice/transcribe.rs` 子进程调用 whisper-cli | 集成测试 T-I-50（mock 二进制）+ 手动 M-19 |

### 1.2 明确不在本范围

- 全局热键守护进程：hlp **不实现**热键监听（见决策 3 与 §1.4 冲突标注），只交付 `hlp voice` 命令与桌面环境绑定指引
- man 结构化索引（§6 第 2 层提及）：继续延后，tldr 已覆盖主力场景
- 模糊/语义匹配：§14 已决策延后，本版不重开
- 语音流式转写（边说边出字）：v0.5 为"按键起停、整段转写"
- 配置管理不管 danger.toml（§7.2 契约：`hlp --trust` 是唯一写者，v0.2 已定，不动）

### 1.3 延迟预算（呼应 §6.1）

| 环节 | 预算 | 说明 |
|---|---|---|
| `hlp config get/list` | < 50ms | 本地 TOML 读取 |
| `hlp config set` | < 100ms | 原子写 + 校验 |
| `-f` kb 命中 | < 50ms | 同第 2 层预算 |
| 录音起停 | 即时 | 外部录制器子进程 |
| 转写（tiny/base 模型，10s 音频，CPU） | 2~10s | whisper.cpp 官方基准量级，不进 §6.1 热路径 |

### 1.4 需求冲突标注（按设计准则，不停工不推翻）

§3.4 原文以"全局热键"为入口。全局热键在 Linux 桌面属桌面环境/合成器职责（X11 全局抓取与 Wayland 协议互不兼容），CLI 程序自实现热键守护既跨不住两个世界也违背 hlp"薄集成"的一贯架构。**处理**：需求语义（用户一个动作即可发起语音输入）由"桌面环境自定义快捷键 → `hlp voice`"承载，文档提供 KDE/GNOME/wm 三份绑定指引；hlp 进程本身不监听热键。此为对 §3.4 的落地诠释而非推翻，`[假设]`该诠释可被接受；若后续要求 hlp 自带热键，需单独立项评估 X11/Wayland 双实现。

### 2.1 `config_cmd.rs`

- 【职责】配置管理子命令。操作对象**仅限** `~/.config/hlp/config.toml`。
- 【公开接口】

```rust
pub enum ConfigAction {
    List,                          // 打印合并后有效配置（TOML 全文，每节附来源注释）
    Get { key: String },           // 点路径键，如 "ollama.model"；stdout 只打值（无 key= 前缀）
    Set { key: String, value: String },  // 写入文件（见契约）；写后立即按既有校验规则验证
    Edit,                          // $EDITOR（缺省 vi）打开配置文件，返回前重新校验
    Path,                          // stdout 打印配置文件绝对路径
}

pub fn run(action: ConfigAction, cfg_path: &Path) -> Result<(), HlpError>;
```

- 【契约】
  - **合法键集合** = config.rs 中 `Config` 全部 serde 字段的点路径（`provider`、`ollama.host`、`ollama.model`、`ollama.timeout_ms`、`cache.enabled`、`cache.exempt_dirs`、`daemon.idle_secs`、`daemon.socket_path`、`kb.enabled`、`kb.min_score`、`kb.index_url`、`explain.language`、`tui.max_candidates`、`voice.*`，见 §3.1）。未知键 → 退出码 3，stderr 列出全部合法键。
  - `set` 的值解析按目标字段类型：bool 只收 `true/false`；整数按十进制；数组收 TOML 数组字面量（如 `["~/a","~/b"]`）；字符串原样。解析失败 → 退出码 2（用法错误）。
  - **保格式写入**：用 `toml_edit` 定位键原位改写，保留注释与键序；键不存在时按节追加（节不存在则追加节）。
  - **写后校验**：改写后重新走 `Config::load` 完整校验；校验失败 → 恢复原文件并报错（退出码 3，附校验原因），不留坏配置。
  - **原子写**：写临时文件（同目录 `.config.toml.tmp`）→ 校验 → rename 覆盖；写入前复制现文件为 `config.toml.bak`（每次 set 覆盖上一版 bak）。
  - `get` 对缺失文件按默认值回答（与引擎行为一致）。
- 【失败语义】文件存在但语法已坏（手动改坏）→ 所有子命令退出码 3 并提示 `hlp config edit` 或手动修复路径；`set` 绝不在坏文件上手术。
- 【新依赖说明】`toml_edit`：toml 序列化重写会丢失注释与键序，而 config.toml 是用户手改的文件，保格式是硬需求；标准库无 TOML 能力，`toml_edit` 是 toml 生态官方的格式保留型编辑库，引入合理。

### 2.2 `fragment.rs`

- 【职责】`hlp -f "<碎片>"`：记得半截命令，补全后半截。
- 【公开接口】

```rust
pub struct FragmentHit { pub command: String, pub source: Source, pub note: String }
// Source 复用 engine 的 Cache/Kb/Llm；note 为 kb 示例描述（verbose 用）

/// 编排：cache(frag: 命名空间) → kb 检索 → LLM 兜底
pub fn complete(cfg: &Config, fragment: &str, max_candidates: usize)
    -> Result<Vec<FragmentHit>, HlpError>;
```

- 【流程】

```
fragment = trim(输入)；为空 → 退出码 2（用法错误）
1. cache.lookup("frag:" + fragment)          ← 命名空间防与自然语言意图撞库
2. kb.search_commands(fragment, limit=3)      ← §2.3，达 1 条即视为命中
   （碎片是命令不是自然语言，不做 min_score 阈值，按匹配度排序即可）
3. 未命中 → Engine 走 daemon-first LLM（碎片补全专用提示词，§3.2）
采纳回流：preexec 学习沿用 v0.3 机制，cache-learn 时 intent 记 "frag:<碎片>"
```

- 【失败语义】LLM 不可达且无 kb 命中 → 退出码 4；无候选 → 退出码 5（同生成路径）。

### 2.3 `kb/mod.rs`（修改：命令形态检索）

```rust
/// 面向碎片补全的检索：匹配 example_cmd 而非描述。
/// 评分：example_cmd 以 fragment 开头 → 3 分；含 fragment 子串 → 2 分；
/// fragment 的每个 token 都按序出现在 example_cmd 中 → 1 分。并列按短命令优先。
/// 返回降序前 limit 条（0 分不入选）。
pub fn search_commands(&self, fragment: &str, limit: usize) -> Vec<KbHit>;
```

- 【契约】大小写敏感（命令是大小写敏感的）；`{{占位符}}` 不参与匹配计分但原样保留在结果里（与 v0.4 决策 4 一致）。

### 2.4 `voice/capture.rs`

- 【职责】采集麦克风音频为 16kHz 单声道 16bit WAV（whisper.cpp 的输入规格）。
- 【公开接口】

```rust
pub struct Recorder { program: String, args_prefix: Vec<String> }  // 探测结果

/// 探测可用录制器：$PATH 依次找 arecord → ffmpeg；都没有 → Err(RecorderUnavailable)
pub fn detect(cfg_recorder: &str) -> Result<Recorder, HlpError>;

/// 录音到临时 WAV：按住式由调用方控制时长（voice 命令为定长 --seconds，默认 10s 上限 60s）。
/// 临时文件建于 $XDG_RUNTIME_DIR 或 /tmp（0600），返回路径；调用方负责删除。
pub fn record(rec: &Recorder, seconds: u32) -> Result<PathBuf, HlpError>;
```

- 【契约】arecord 参数：`-q -f S16_LE -r 16000 -c 1 -d <secs> <wav>`；ffmpeg 参数：`-y -f alsa -i default -t <secs> -ar 16000 -ac 1 <wav>`（stderr 静默）。**不经 shell**，argv 直执。
- 【失败语义】录制器启动失败/超时（seconds+5s 兜底强杀）→ `HlpError::VoiceUnavailable`，退出码 6，stderr 提示安装 alsa-utils/ffmpeg。

### 2.5 `voice/transcribe.rs`

- 【职责】调用 whisper.cpp 官方 CLI（`whisper-cli`，旧版二进制名 `main`）转写。
- 【公开接口】

```rust
/// 校验配置：whisper_bin 可执行 + model_path 存在；不满足 → VoiceUnavailable（退出码 6，
/// stderr 附配置指引：hlp config set voice.model_path <路径>）
pub fn check(cfg: &VoiceConfig) -> Result<(), HlpError>;

/// 转写：whisper-cli -m <model> -f <wav> --no-timestamps -l auto -otxt
/// 解析 stdout 纯文本；去首尾空白、合并多行为单行空格分隔。
/// 空转写（静音/未识别）→ Err(NoCandidates)（退出码 5）
pub fn transcribe(cfg: &VoiceConfig, wav: &Path) -> Result<String, HlpError>;
```

- 【契约】超时 = 120s（CPU tiny/base 模型 60s 音频的上限量级）；子进程非零退出 → stderr 原文透传前 200 字符。语言自动检测（`-l auto`），转写文本语言即意图语言，天然满足 §13"解释语言跟随意图"的下游判定。
- 【决策依据】whisper.cpp 走**外部二进制子进程**而非库绑定，见决策 1。

### 2.6 `voice/inject.rs`

- 【职责】把文本注入用户当前输入位置。
- 【公开接口】

```rust
pub enum Injector { Xdotool, Wtype, Clipboard, Stdout }

/// 探测链（cfg 覆盖优先）：$XDG_SESSION_TYPE=x11 → xdotool；wayland → wtype；
/// 都无 → 剪贴板（xclip/xsel/wl-copy 任一）；再无 → Stdout（打印文本，用户手贴）
pub fn detect(cfg_inject: &str) -> Injector;

/// 注入：Xdotool=`xdotool type --delay 12 -- <text>`；Wtype=`wtype -- <text>`；
/// Clipboard 写入并 stderr 提示"已在剪贴板，Ctrl+V 粘贴"；Stdout 直接 println。
/// argv 直执不经 shell；文本以参数传（-- 后），无注入面。
pub fn inject(inj: &Injector, text: &str) -> Result<(), HlpError>;
```

- 【契约】注入失败（如 X11 下 xdotool 存在但无 DISPLAY）→ 自动降一级重试，全部失败 → Stdout 兜底，永不丢文本。降级过程在 `--verbose` 时注记。

### 2.7 `voice/mod.rs`

- 【门面】

```rust
pub struct VoiceOpts {
    pub seconds: u32,        // --seconds，默认 10，上限 60
    pub translate: bool,     // --translate：转写后继续走 Engine 生成命令
    pub stdout_only: bool,   // --stdout：不注入，结果打印到 stdout（脚本可用）
}

pub fn run(cfg: Config, opts: VoiceOpts) -> Result<(), HlpError>;
```

- 【流程】

```
check(whisper 配置) → detect(Recorder) → detect(Injector)
 → stderr 提示 "● 录音中（Ns）…"（TTY 时）→ record → transcribe
 → stderr 回显转写文本
 → opts.translate？否 → inject(转写文本)
            是 → Engine::run(one_line 语义，intent=转写文本)
                 → 生成成功 → inject(命令)（--stdout 时打印到 stdout，纯净协议）
                 → 生成失败 → 回退注入转写文本，stderr 注记（退出码仍按引擎错误码）
```

- 【用户确认点】`--translate` 注入的是**命令文本而非执行**——执行权仍在用户回车（§7.3），voice 路径不接 danger 熔断（熔断发生在 shell 侧 v0.2 契约与 TUI 侧，注入只是把字放进输入行）。

### 2.8 `cli.rs` / `main.rs`（修改）

- 【新增】
  - `-f, --fragment "<碎片>"`：与 `--one-line`/`--alt`/`--stream`/`--verbose` 兼容（同属生成族）；stdout 协议同生成路径（top1 单行 / --alt 每行一条）。

## 3. 数据结构与协议

### 3.1 config.toml 新增一节（默认值 + 校验）

```toml
[voice]
whisper_bin = "whisper-cli"   # whisper.cpp CLI 路径；旧版编译产物名为 "main"
model_path = ""               # GGUF 模型绝对路径；空 = 未配置（voice 命令时报配置指引）
recorder = "auto"             # auto | arecord | ffmpeg
inject = "auto"               # auto | xdotool | wtype | clipboard | stdout
```

校验：`recorder`/`inject` 非枚举值 → ConfigInvalid（退出码 3）；`model_path` 非空但为相对路径 → 退出码 3；`whisper_bin` 含路径分隔符时必须是绝对路径。`model_path = ""` 是**合法**配置（未启用语音），运行 `hlp voice` 时才检查并报退出码 6。未知字段仍 deny。

### 3.2 碎片补全提示词（prompt.rs 新增构建器）

```
你是 shell 命令补全器。用户记得命令的前半截，输出最可能的完整命令。
规则：
1. 只输出 JSON：{"candidates": ["<完整命令1>", "<完整命令2>", ...]}，最多 {max} 条
2. 每条候选必须以用户给的碎片开头（逐字前缀）
3. 保持碎片原样，不修正、不翻译、不加解释
```

兜底解析复用 v0.1 两级解析；**后缀校验**：返回候选不以 fragment 开头 → 丢弃该候选，全丢 → NoCandidates（退出码 5）。

### 3.3 stdout 协议（增量）

| 调用 | stdout | 退出码 |
|---|---|---|
| `hlp -f "<碎片>"` | top1 完整命令（单行，纯净） | 0/2/3/4/5 |
| `hlp -f --alt "<碎片>"` | 每行一条候选 | 同上 |
| `hlp config get <key>` | 值本身（数组/字符串不带引号） | 0/2/3 |
| `hlp config list` | 合并后 TOML 全文（节首注释 `# 来源: file/default`） | 0/3 |
| `hlp config path` | 绝对路径单行 | 0 |
| `hlp voice --stdout` | 转写文本单行；`--translate` 时为命令单行（纯净） | 0/4/5/6 |
| `hlp voice`（无 --stdout） | 空（文本走注入，stdout 不输出） | 0/4/5/6 |

### 3.4 文件布局（增量）

| 路径 | 内容 | 权限 |
|---|---|---|
| `~/.config/hlp/config.toml.bak` | config set 前的上一版备份 | 0600 |
| `$XDG_RUNTIME_DIR/hlp-voice-<pid>.wav` 或 `/tmp/...` | 录音临时文件，转写后即删 | 0600 |
| whisper GGUF 模型 | 用户自管，`voice.model_path` 指向 | — |

## 4. 关键流程

### 4.1 config set 的安全写入

```
hlp config set ollama.model qwen2.5-coder:7b
 → 读 config.toml（不存在 → 从默认值构造文档树）
 → 键合法性检查（不在合法键集合 → exit 3 列键表）
 → 值按目标类型解析（失败 → exit 2）
 → cp config.toml config.toml.bak（文件存在时）
 → toml_edit 原位改写 → 序列化到临时文件
 → 以新内容跑完整 Config::load 校验 → 失败则丢弃临时文件，exit 3（原文件不动）
 → rename 临时文件覆盖正式文件 → stderr "已写入（备份：...bak）"，exit 0
```

### 4.2 语音输入全流程

```
桌面环境热键（用户自配）→ hlp voice --seconds 8
 → whisper 配置检查（未配模型 → exit 6 + 配置指引）
 → 探测录制器/注入器
 → "● 录音中（8s）…"（stderr）
 → record → WAV → transcribe → "转写：把 jpg 缩到 800 宽"（stderr）
 → inject("把 jpg 缩到 800 宽")        ← 用户在输入行看到文字，按 Ctrl+G 走既有 v0.2 流
或 --translate：
 → Engine.run(intent=转写文本) → inject("convert ... -resize 800x ...") ← 用户回车才执行
```

### 4.3 碎片补全三层链

```
hlp -f "tar -xzvf"
 → cache.lookup("frag:tar -xzvf")      命中 → stdout（source=cache）
 → kb.search_commands("tar -xzvf")     命中 → stdout top1（source=kb，如 `tar -xzvf {{归档文件}}`）
 → daemon-first LLM（碎片提示词 + 前缀校验）
采纳回流（v0.3 preexec 机制）：用户执行了补全结果 → cache-learn intent="frag:tar -xzvf"
```

## 5. 错误分类

v0.1~v0.4 退出码全部保留。新增：

## 9. 决策与权衡

- **决策 1：whisper.cpp 走外部二进制子进程，不用 whisper-rs 绑定**。whisper-rs 要把 whisper.cpp 的 C++/GGML 编译链拉进 cargo build（构建时间、交叉编译、模型格式升级都跟走），违背单二进制与"薄"架构；子进程方案让用户自选 whisper.cpp 版本与模型（GGUF 生态更新快），hlp 只约定 CLI 参数面。被拒绝的备选：whisper-rs（构建链沉重）、自建 HTTP 转写服务（§3.4 明确本地 CLI 形态）。
- **决策 2：录音走系统录制器（arecord/ffmpeg）子进程，不引入 cpal**。cpal 是 Rust 唯一成熟音频采集库，但 ALSA/PulseAudio/PipeWire 的兼容矩阵与设备枚举复杂度全压给 hlp；arecord 在目标平台（Linux 桌面）几乎随 alsa-utils 必有，ffmpeg 兜底。被拒绝的备选：cpal（新依赖 + 设备问题支持成本）。
- **决策 3：hlp 不实现全局热键，交付 `hlp voice` 命令 + 桌面环境绑定指引**（§1.4 冲突标注）。X11 全局抓取（XRecord）与 Wayland（各合成器私有协议）无法统一实现，而 KDE/GNOME/i3/hyprland 都内置"自定义快捷键执行命令"——桌面环境才是热键的正确位置，hlp 自实现只会覆盖一半用户且引入常驻进程。被拒绝的备选：X11 全局热键守护（Wayland 用户被抛弃 + 常驻进程违背 §6.2"不常驻"精神）。
- **决策 4：注入工具链探测降级（xdotool → wtype → 剪贴板 → stdout），永不丢文本**。注入是语音链路的最后一厘米，桌面环境差异最大；探测链保证任何环境都有可用落点（最差是把文本打印出来用户手贴）。被拒绝的备选：只支持 xdotool（Wayland 用户无语音可用）、引入 enigo 等 Rust 输入库（同样跨不了 Wayland 合成器差异）。
- **决策 5：默认注入转写原文，`--translate` 才注入生成命令**。§3.4 原文语义是"转写结果经剪贴板或 xdotool/wtype 注入"——语音是输入形态不是生成快捷键，注入原文后用户走既有 Ctrl+G 流程，所有安全契约（熔断/确认）原样生效；`--translate` 合并两步为便利选项，但注入的仍是文本而非执行（§7.3）。被拒绝的备选：默认直接生成（语音误识别直接变成命令上屏，少一道人工检查）。
- **决策 6：config set 用 toml_edit 保注释保键序，写后全量校验 + 原子写 + .bak**。config.toml 是用户手改的文件（带注释），toml 序列化重写会抹掉注释——不可接受；写后校验保证 set 永远不能产出引擎拒绝加载的配置。被拒绝的备选：toml 序列化重写（丢注释）、文本行级手术（键在节内任意位置时必错）。
- **决策 7：config 子命令只管 config.toml，不碰 danger.toml**。v0.2 已确立 `hlp --trust` 是 danger.toml 唯一写者、撤销走手动编辑的契约；两个写入口径并存只会制造"哪个为准"的困惑。被拒绝的备选：config set 同步支持 danger.trust（写者分裂）。
- **决策 8：`-f` 的缓存复用历史缓存但加 `frag:` 命名空间前缀**。碎片与自然语言意图的命中语义完全不同（前缀匹配对碎片是常态），同库混存会让"列出大文件"和"ls -l"互相污染命中；加前缀零 schema 变更即隔离。被拒绝的备选：独立表（迁移成本，收益为零）。
- **决策 9：`-f` 的 kb 检索按命令形态匹配（example_cmd 前缀/子串/按序 token），不做 min_score 阈值**。碎片是命令不是自然语言，v0.4 的召回式意图评分不适用；命令前缀匹配的误命中天然低，排序即可。被拒绝的备选：复用 score()（中文评分逻辑对 ASCII 碎片无意义）。
- **决策 10：转写语言自动检测（whisper `-l auto`），不做配置项**。§13 已定"解释语言跟随意图语言"，语音意图的语言由用户说话决定；whisper 的检测准确率足够，配置项只会被设错。被拒绝的备选：`[voice] language` 配置（与自动检测冲突时以谁为准是新的困惑源）。

## 10. 遗留风险（实现模型最易搞错的点）

1. **toml_edit 的键路径定位**：`ollama.model` 要定位到 `[ollama]` 节内的 `model` 键，而非顶层新建一个名为 `"ollama.model"` 的键——实现者若用字符串拼 key 必错；T-U-68/71 是守门测试（注释保留 + 键路径快照）。
2. **假外部工具的可测试性**：capture/transcribe/inject 的探测函数必须把 $PATH 查找做成可注入参数，否则集成测试无法在不安装 arecord/xdotool 的 CI 环境跑——实现者容易把 `which` 调用写死在业务函数里，导致 T-I-50~52 只能手工测。
3. **whisper-cli 输出格式漂移**：不同版本 whisper.cpp 的 stdout 可能带时间戳行（`[00:00:00.000 --> ...]`）或空行，清洗逻辑（T-U-76）必须按"剔除非文本行"而非"假定纯净"实现；`--no-timestamps` 只是首选防御，解析层仍要兜底。
4. **录音兜底强杀**：录制器子进程若因设备占用挂死，`-d <secs>` 不会生效——实现必须独立计时 seconds+5s 后 kill 子进程，否则 voice 命令会永久挂起（T-I-50 的假 arecord 应包含"永不退出"变体验证强杀）。
5. **`-f` 的 LLM 候选前缀校验不可省**：小模型常见错误是"补全"时改写用户碎片（修正常见拼写）——不改写是硬契约（§3.2 规则 3），实现者若省略后缀校验，用户体验会从"补全"变成"被纠正"，T-U-75 守门。
6. **voice --translate 的失败回滚语义**：引擎失败时已注入的转写文本**不撤销**（注入动作无法撤销，且文本对用户有用）——实现者容易试图"清理现场"反而把用户输入行搞乱；正确做法是 stderr 注记 + 透传引擎退出码（§5 表格锁定）。
