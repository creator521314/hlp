### 1.2 明确不在本范围

- `hlp -f` 碎片补全（§3.3）——路线表未列入 v0.4，延后
- 模糊/向量匹配（缓存层与知识库层均不做）——§14 已决策延后

- TUI 内的流式逐字渲染复用到 shell widget 之外的场景——TUI 内部用流式，不新增对外协议语义

### 1.3 延迟预算（呼应 §6.1）

| 环节 | 预算 | 说明 |
|---|---|---|
| kb 命中返回 | < 50ms | 本地 SQLite + 内存评分；不含 LLM |
| `-x` 纯本地标注（`--offline`） | < 100ms | 拆段 + 逐段 kb 查页 |
| `-x` 含 LLM 综合 | 1~3s | 一次性调用（决策 6），复用 daemon 保温 |
| TUI 启动到首屏 | < 300ms | ratatui 初始化 + 首帧；不含生成 |
| TUI 生成（热 daemon） | 感知 < 500ms | 复用 v0.3 `generate_stream` |
| dry-run 执行 | < 1s（上限 5s 超时） | 只读变换命令，argv 直执 |
| `kb-update` | 网络不定 | 显式操作，打印进度到 stderr |

**冷启动红线**：`--one-line` / `--stream` / `--check` 路径不得因引入 ratatui/crossterm 变慢——TUI 代码只在 `tui` 入口初始化；T-I-41 做启动耗时回归。

### 2.1 `kb/parse.rs`

- 【职责】把 tldr-pages 的 markdown 页解析为结构化条目。tldr 页格式（官方约定）：

```markdown
# find

> 递归查找目录树中的文件。
> More information: <https://...>.

- 按扩展名查找文件：

`find {{根路径}} -name '{{*.ext}}'`
```

- 【公开接口】

```rust
pub struct Page {
    pub command: String,           // 标题（# 后内容），小写
    pub description: String,       // 第一条 > 引用（跳过 More information 行）
    pub examples: Vec<Example>,
}
pub struct Example {
    pub description: String,       // - 列表项文字（去尾部冒号）
    pub command: String,           // 反引号内命令，{{占位符}} 原样保留
}

/// 解析单页 markdown；结构不合（无标题/无示例）→ Err(原因)
pub fn parse_page(markdown: &str) -> Result<Page, String>;
```

- 【契约】只接受上述官方结构；容忍空行与行尾空白差异；`More information:` 行不进入 description。
- 【失败语义】单页解析失败返回 Err，由 fetch 层计数跳过，不中断整批导入。

### 2.2 `kb/score.rs`

- 【职责】意图与 kb 示例的相关性评分（§6.1"关键词匹配，初期不上向量检索"的落地）。
- 【公开接口】

```rust
/// 分词：ASCII 单词小写化按非字母数字切分；CJK 连续段取单字 + 相邻二字组（bigram）
pub fn tokenize(s: &str) -> Vec<String>;

/// 评分：recall = |意图token ∩ 描述token| / |意图token|（空意图 → 0.0）
/// 命中页命令名（意图含该命令名原文，如 "find"）额外 +0.2，上限 1.0
pub fn score(intent_tokens: &[String], example: &Example, page: &Page) -> f64;
```

- 【契约】评分是确定性的纯函数；阈值判定在 `kb/mod.rs`，不在此处。
- 【算法说明】这是 §14 开放问题的 v0.4 解答（`[假设]`）：召回式评分偏向"意图里的关键词都被示例覆盖"。有效性依赖 tldr 中文页（pages.zh）覆盖率，属经验参数——阈值做成配置项（§3.1），测试用 fixture 锁定算法行为而非真实语料效果。

### 2.3 `kb/mod.rs`

- 【公开接口】

```rust
pub struct KbHit {
    pub command: String,          // 示例命令（含 {{占位符}}，原样）
    pub description: String,      // 示例描述（展示用）
    pub page: String,             // 来源命令名
    pub score: f64,
}

pub struct Kb { /* Store 连接只读复用 + min_score + enabled */ }

impl Kb {
    pub fn from_config(cfg: &Config) -> Result<Kb, HlpError>; // enabled=false → 内部空实现
    /// 意图 → 达阈值（>= min_score）的命中，按 score 降序，最多 3 条
    pub fn lookup(&self, intent: &str) -> Vec<KbHit>;   // 内部吞错返回空 vec（同 v0.3 缓存哲学）
    pub fn status(&self) -> KbStatus;                   // { pages: u32, examples: u32, updated_at: Option<i64> }
    /// 按命令名取页（explain 本地标注用），platform 优先 linux 回退 common
    pub fn page_of(&self, command: &str) -> Option<Page>;
}
```

- 【行为契约】kb 是加速器不是硬依赖（同 v0.3 决策 3）：查询失败一律返回空，不阻断生成。语料双语：中文意图同时匹配 pages.zh 与 pages（英文）语料，英文意图只匹配 pages（英文）——避免中文页描述对英文意图的噪声命中。

### 2.4 `kb/fetch.rs`（kb-update）

- 【职责】显式联网更新语料：下载 tldr 官方 release 的 `tldr.zip` → 解压 → 取 `pages/`（英文）、`pages.zh/`（中文）、`pages/linux/`、`pages.zh/linux/`、`pages/common/`、`pages.zh/common/` → 逐页 `parse_page` → 写入 SQLite。
- 【公开接口】

```rust
/// 全量重建：先清空 kb 两表再插入（同事务）。返回导入统计。
pub fn update(db_path: &Path, progress: &mut dyn FnMut(&str)) -> Result<KbStats, HlpError>;
pub struct KbStats { pub pages: u32, pub examples: u32, pub skipped: u32 }
```

- 【下载地址】`https://github.com/tldr-pages/tldr/releases/latest/download/tldr.zip`（`[kb] index_url` 可覆盖，便于代理/镜像）。
- 【失败语义】网络失败 / zip 损坏 / 目录结构不符（缺 `pages/`）→ `HlpError::KbUnavailable`，退出码 6，stderr 给原因与手动下载指引；DB 保持更新前状态（清空+插入在一个事务里，失败整体回滚）。
- 【新依赖说明】`zip` crate（default-features = false，纯 Rust 解压）：标准库无 zip 能力，tar 不支持 zip 格式，引入合理。

### 2.5 `explain/split.rs`

- 【职责】把命令按**顶层** `|` 拆段——单双引号内与 `\|` 转义不拆。
- 【公开接口】

```rust
/// 拆段。引号未闭合 → 按已扫描内容尽力拆（不报错，解释器对残缺输入应宽容）。
/// 每段 trim；空段（如 "a |"）被丢弃。
pub fn split_pipeline(cmd: &str) -> Vec<String>;

/// 提取段的基础命令名：跳过前导环境变量赋值（FOO=bar）与 sudo/doas，
/// 取首个有效 token（去引号）。空段 → None。
pub fn base_command(segment: &str) -> Option<String>;
```

- 【契约】纯函数，不执行任何内容。这是全文最重要的正确性点之一，单元测试必须覆盖引号/转义/赋值前缀（T-U-51~53）。

### 2.6 `explain/lang.rs`

- 【职责】解释语言判定（§13"解释语言跟随意图语言"在 `-x` 场景的落地，决策 5）。
- 【公开接口】

pub enum Lang { Zh, En }

pub fn detect(cfg_lang: &str, intent_or_command: &str, env_lang: Option<&str>) -> Lang;

### 2.7 `explain/mod.rs`

- 【职责】`-x` 与 TUI 逐段解释的编排：拆段 → 本地标注 →（可选）LLM 一次性综合。
- 【公开接口】

```rust
pub struct Segment { pub cmd: String, pub note: String }   // note 为解释文字
pub struct Explanation { pub segments: Vec<Segment>, pub lang: Lang, pub source: ExplainSource }
pub enum ExplainSource { Local, Llm, Mixed }   // Mixed = 部分段来自 kb、部分来自 LLM

/// offline=true → 只用 kb 本地标注（无 kb 页的段 note 为 ""，渲染层显示"（无本地注解）"）
pub fn explain(cfg: &Config, command: &str, offline: bool) -> Result<Explanation, HlpError>;
```

- 【流程】

```
split_pipeline(cmd)
 → 每段 base_command → kb.page_of 取本地页（标注素材，<10ms/段）
 → offline？是 → 直接渲染本地标注
          否 → 一次 LLM 调用（daemon v2 Explain op，失败回退直连，再失败回退本地标注）：
               system prompt 注入：全部段 + 各段 kb 页内容（截断）+ 语言要求
               期望返回 {"segments":[{"cmd":"...","note":"..."}]}
               解析复用 v0.1 两级解析哲学：JSON 失败 → 按行兜底对齐段序
 → 段数对不齐的兜底：以 split 结果为准，LLM 缺段用 kb 标注补，多出的丢弃
```

- 【失败语义】LLM 不可达且无本地标注 → `HlpError::ProviderUnreachable`（退出码 4）；有本地标注则降级输出（`--verbose` 注记降级）。

### 2.8 `dryrun.rs`

- 【职责】把命令变换为**只读预览命令**并受限执行。安全核心：永远不执行原命令。
- 【公开接口】

```rust
pub enum DryPlan {
    /// argv 直执（不经 shell）：程序 + 参数
    Exec { program: String, args: Vec<String>, note: String },
    /// 该命令不支持 dry-run（含永不支持的 fatal 类）
    Unsupported { reason: String },
}

/// 仅支持单段命令（含管道 → Unsupported）。引号已按 shell 词法切分为 token。
pub fn plan(command: &str) -> DryPlan;

/// 执行 DryPlan::Exec：std::process::Command argv 直执（无 shell、无 glob 展开），
/// 捕获 stdout/stderr 各截断 4KB，超时 5s 强杀。返回展示文本。
pub fn run(plan: &DryPlan) -> Result<String, HlpError>;
```

- 【内置变换表】（代码内置，不开放配置——决策 10）

| 基础命令 | 变换 | 预览语义 |
|---|---|---|
| `rm` / `rm -rf` / `rmdir` | `ls -ld -- <原参数>` | 列出将被删除的对象（glob 不展开，见遗留风险 2） |
| `rsync` | 原 argv 追加 `-n` | rsync 原生 dry-run |
| `git clean` | 原 argv 追加 `-n` | git 原生 dry-run |
| `mv` / `cp` | `ls -ld -- <源参数（末位参数之前的全部）>` | 列出源对象 |
| `dd` / `mkfs*` / `shutdown` / `reboot` | 永不支持 | fatal 级命令不给预览假象 |

- 【注入防护】`plan` 先用词法分析切 token；任何 token 含 `;`、`&`、`` ` ``、`$`、`<`、`>`、`\n` → `Unsupported{reason: "含特殊字符，不予预览"}`。执行不经 shell，无命令替换面。
- 【失败语义】执行失败（程序不存在等）→ 错误信息进返回文本（exit 0，stderr 注记）——dry-run 是辅助预览，失败不上升为进程错误。

### 2.9 `tui/` 模块

- 【职责】§4.3 富交互卡片。技术选型 ratatui + crossterm（§9 已定）。
- 【入口】

```rust
/// 进入 TUI。intent 为 None → 首屏为输入框。非 TTY → HlpError::TuiUnavailable（退出码 6）。
/// 退出后进程退出码：用户按 E 执行并成功 → 0；普通退出（q/Esc）→ 0。
pub fn run(cfg: Config, intent: Option<String>) -> Result<(), HlpError>;
```

- 【状态机（app.rs）】

```
Input(意图输入框) --回车--> Generating --流式快照--> Generating(更新预览)
Generating --Done--> Ready { candidates, selected, explanation }
Ready --a--> Ready(切换选中候选；轮询 candidates，含 kb 组)
Ready --r--> Refine(修正输入框) --回车--> Generating(拼装 refine 提示词)
Ready --d--> DryRunPreview(执行 dryrun::plan+run，底部窗格展示)
Ready --x--> Ready(重新加载/刷新逐段解释)
Ready --c--> Ready(复制选中命令，OSC52；状态栏提示"已复制")
Ready --e--> DangerGate：danger::check(选中命令)
               Clean/Info → ConfirmExec(y/N)
               Warning    → ConfirmWarning(y/N)（信任命中视为 Clean）
               Fatal      → ConfirmFatal(要求输入完整命令原文)
             Confirm* 确认 → Executing(sh -c 选中命令，输出进入滚动窗格) → Done
DryRunPreview/Confirm*/Done --Esc--> Ready
任意状态 --q--> 退出
```

- 【用户确认点】`[E]` 是 v0.4 唯一的命令执行路径，必须依次经过 danger 熔断门；这与 v0.2 shell 侧的确认契约同源（同一 `danger::check`），TUI 不复读规则文本，只呈现级别与确认要求。
- 【候选排序（§14 融合问题的 TUI 侧解答）】候选列表分组：kb 命中组（标 `[知识库]`，按 score 降序）在前，LLM 组（标 `[LLM]`）在后。两组不混排打分——理由见决策 3。
- 【渲染（ui.rs）】布局严格按 §4.3 卡片：顶部命令区（当前选中候选）、逐段解释区、底部快捷键行 `[D]ry-run [C]opy [E]xecute [R]efine [A]lternative [Q]uit`。终端高度不足 10 行时退化为纯命令行渲染（只画命令 + 快捷键行）。
- 【依赖说明】`ratatui` + `crossterm`：§9 选型已定 ratatui；crossterm 是 ratatui 官方推荐后端，二者为 TUI 必需，无标准库替代。
- 【复制】OSC52 转义序列写 `/dev/tty`（不经 stdout，避免污染），终端不支持时静默失败 + 状态栏提示改用鼠标选择。不引入 arboard（决策 11）。

### 2.10 `cli.rs` / `main.rs`（修改）

- 【新增参数/子命令】
  - `-x, --explain "<命令>"`：解释模式。`--offline` 修饰符只用本地标注。与生成参数（位置意图、`--one-line`/`--stream`/`--alt`）互斥。
  - `--tui [意图]`：进入 TUI。意图可缺省（首屏输入框）。
  - 裸 `hlp`（无任何参数）：stdout 是 TTY → 等价 `--tui`；非 TTY → clap 用法错误（退出码 2）。
  - `--dry-run "<命令>"`：本地 dry-run，stdout 输出预览文本，退出 0；`Unsupported` → stdout 空、stderr 说明、退出 0。
  - `hlp kb-update`：更新语料（显式联网），成功打印统计到 stderr，退出 0；失败退出 6。
  - `hlp kb-status`：打印 `pages=N examples=N updated_at=...`（key=value，stdout），未建库时 `pages=0 examples=0 updated_at=`，退出 0。
- 【分发】`-x` / `--dry-run` / `kb-*` 为本地优先路径：`-x` 默认经 daemon v2 Explain op（失败回退直连）；`--dry-run`/`kb-*` 不碰 LLM、不拉起 daemon。

### 2.11 `daemon/protocol.rs`（修改：协议 v2）

```rust
pub const PROTOCOL_VERSION: u32 = 2;

pub enum Op {
    // v0.3 既有：Generate / Learn / Clear / Ping（不变）
    Explain { command: String, lang: Lang, offline: bool },   // 新增
}

pub enum Event {
    // 既有：Chunk / Done / Ok / Error（不变）
    Explanation { segments: Vec<Segment>, source: ExplainSource },  // 新增终结事件
}
```

- 【兼容】daemon 对 `v != PROTOCOL_VERSION` 回 `Error{protocol}`；v0.4 客户端遇到 protocol 错误 → 回退直连 Provider 路径（复用 v0.3 决策 5 的韧性模式）。旧 v0.3 daemon 收到 v2 请求同样回 protocol 错误——升级二进制后残留在跑的旧 daemon 不会出错，只是 explain 走直连（遗留风险 6 提示用户重启 daemon）。
- 【server 侧】Explain 处理：offline → 本地标注；否则 Provider 一次性调用 + 本地标注兜底合成。

### 2.12 `provider/mod.rs`（修改）

```rust
pub struct GenerateRequest {
    // 既有字段不变
    /// TUI 卡片需要逐段解释时置 true：Provider 请求扩展输出 schema
    /// {"candidates":[...], "segments":[{"cmd":"...","note":"..."}]}
    /// （ollama format 同步扩展；兜底解析时 segments 缺省为空 vec）

```

- 【契约】`segments` 相对 top1 候选而言；Provider 清洗职责不变；解析失败时 segments 为空，TUI 退化为"按 X 重新获取解释"（走 explain 模块）。

## 3. 数据结构与协议

### 3.1 config.toml 新增三节（默认值 + 校验）

```toml
[kb]
enabled = true              # 第 2 层开关
min_score = 0.6             # 命中阈值，0.0..=1.0
index_url = ""              # 空 = 官方 release 地址（§2.4）

[explain]
language = "auto"           # auto | zh | en

[tui]
max_candidates = 3          # 1..=8；TUI 生成时请求的候选数
```

校验：`min_score` 越界 / `language` 非三值之一 / `max_candidates` 越界 / `index_url` 非空但不是 http(s) → ConfigInvalid（退出码 3）。未知字段仍 deny。

### 3.2 SQLite schema 迁移（user_version 1 → 2）

```sql
CREATE TABLE IF NOT EXISTS kb_pages (
  command     TEXT NOT NULL,
  lang        TEXT NOT NULL,          -- 'en' | 'zh'
  platform    TEXT NOT NULL,          -- 'common' | 'linux'
  description TEXT NOT NULL,
  PRIMARY KEY (command, lang, platform)
);
CREATE TABLE IF NOT EXISTS kb_examples (
  id          INTEGER PRIMARY KEY,
  command     TEXT NOT NULL,          -- 所属页命令名
  lang        TEXT NOT NULL,
  example_cmd TEXT NOT NULL,          -- 含 {{占位符}} 原样
  example_desc TEXT NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_kb_examples_cmd ON kb_examples(command, lang);
CREATE TABLE IF NOT EXISTS kb_meta (k TEXT PRIMARY KEY, v TEXT);  -- updated_at 等
PRAGMA user_version = 2;
```

迁移策略：Store::open 检测 `user_version < 2` → 执行上述 DDL 并置 2。v0.3 的 `entries` 表不动。kb 两表与历史缓存同库（决策 2）：`hlp --clear` 只清 `entries`（历史），**不清 kb 语料**（语料是公共数据不是隐私数据）；语义写入 README。

### 3.3 `-x` 的 stdout 协议

`-x` 是**面向终端的阅读型输出**（首个 stdout 携带散文的模式；它不服务 shell 集成，不受纯净协议约束）：

```
find . -type f -size +100M -exec du -h {} + | sort -rh

  find . -type f -size +100M    递归查找普通文件，只保留大于 100MB 的
  -exec du -h {} +              对命中的文件批量计算人类可读大小
  sort -rh                      按数值倒序排列
```

规则：首行原样回显命令 → 空行 → 每段两空格缩进，段命令与解释间以多空格对齐。`--verbose` 时 stderr 输出 source（local/llm/mixed）与耗时。机器消费场景用 `--json`（输出 `Explanation` 的 JSON，供 TUI 调试与测试断言）。

### 3.4 `--dry-run` 的 stdout 协议

```
$ hlp --dry-run "rm -rf /tmp/testdata"
预览（未执行原命令）：ls -ld -- -rf /tmp/testdata
drwxrwxr-x 3 user user 4096 Nov 4 20:00 /tmp/testdata
```

首行说明变换后的预览命令（`ls` 的参数含 `-rf` 属正常——它作为 `ls` 的操作数原样列出），其后为预览输出。Unsupported 时 stdout 为空、stderr 一行原因、退出 0。

## 4. 关键流程

### 4.1 三层生成链（v0.4 完整形态）

```
hlp --one-line "列出大文件"
 → cache.lookup            命中 → stdout 单行（source=cache）
 → kb.lookup("列出大文件")
     tokenize → 对语料示例评分 → top score ≥ min_score？
       是 → stdout 单行（source=kb，含 {{占位符}} 原样；verbose 注记分数）
       否 ↓
 → daemon-first LLM（v0.3 路径不变）
```

kb 层失败（DB 未建/语料为空/查询错误）→ 等同未命中，静默落到第 3 层。

### 4.2 kb-update 流程

```
hlp kb-update
 → 下载 index_url（超时 60s，进度到 stderr）→ ~/.cache/hlp/tldr.zip
 → zip 打开，枚举 entries：仅取 pages/{common,linux}/*.md 与 pages.zh/{common,linux}/*.md
 → 逐页 parse_page；失败计数 skipped++
 → 事务：DELETE kb_pages/kb_examples → 批量 INSERT → kb_meta.updated_at=now → COMMIT
 → stderr 打印 "已导入 N 页 / M 条示例（跳过 K）"，退出 0
任何一步失败 → 事务回滚（DB 保持旧语料），退出码 6
```

### 4.3 `-x` 解释流程

```
hlp -x "awk '{print $2}' a.log | sort | uniq -c"
 → split_pipeline → ["awk '{print $2}' a.log", "sort", "uniq -c"]
 → lang detect（命令无 CJK → 看 LANG）
 → 每段 base_command → kb.page_of 取本地页素材
 → offline？否 → daemon v2 Explain（protocol 错 → 直连 Provider；仍败 → 本地标注兜底）
 → LLM 返回 segments JSON → 按 split 段序对齐合成
 → stdout 按 §3.3 渲染
```

### 4.4 TUI 主流程

```
hlp --tui ["把 jpg 缩到 800 宽"]
 → TTY 检查（非 TTY → 退出码 6）
 → intent 空 → Input 状态；否则直接 Generating
 → Generating：kb.lookup 先行（命中组）+ generate_stream（want_explanation=true）
     快照逐次更新命令预览区；Done → Ready
 → Ready：渲染 §4.3 卡片（命令 + 逐段解释 + 快捷键行）
   按键循环：a/d/c/x/r/e/q 按 §2.9 状态机流转
   e → danger::check → 确认门 → sh -c 执行 → 输出窗格 → Esc 回 Ready（可继续 refine）
```

### 4.5 Refine 提示词拼装（决策 8 的补充）

```
Refine 输入 "不对，只要 jpg" 时，新请求的 user 消息为：
  原始意图：{intent}
  上一次生成：{current_command}
  修正要求：{refine_text}
  （已出现过的候选不再重复：{seen_candidates}）
system prompt 不变（v0.1 契约 + want_explanation 扩展）。
Provider trait 不改签名——多轮上下文由 prompt 拼装承载。
```

## 5. 错误分类

v0.1/v0.2/v0.3 退出码全部保留。新增/变化：

## 9. 决策与权衡

- **决策 1：tldr 语料用 `kb-update` 显式下载官方 `tldr.zip`，不打包进二进制**。打包会让单二进制膨胀数 MB 且每次发版都要同步上游语料；显式更新符合 §8"数据本地"且网络动作显式化。被拒绝的备选：build.rs 编译期内嵌（发布流水线耦合上游）、运行时逐页在线拉取（违背本地化定位）。
- **决策 2：kb 语料与历史缓存同存 `hlp.sqlite`（user_version 2 迁移）**。单文件便于备份与权限控制（0600），rusqlite 已是依赖零新增；`--clear` 只清历史表、不动公共语料，语义清晰。被拒绝的备选：独立 kb 文件（两个 DB 文件两倍运维面）、sled/redb（无必要换存储引擎）。
- **决策 3（§14 开放问题"tldr 卡片与 LLM 输出融合排序"的解答）：不混排打分——kb 达 `min_score` 阈值即整体优先**（`--one-line` 路径短路返回；TUI 路径 kb 组排前并标来源）。理由：kb 示例经人工编写、质量恒定，LLM 输出质量随模型波动，二者置信度量纲不同，混排打分需要标定实验，超出 v0.4 预算；阈值短路同时兑现 §6.1 的 50ms 预算。被拒绝的备选：统一置信度评分混排（无量纲依据）、kb 永远排后只做补充（第 2 层形同虚设）。
- **决策 4：kb 命中的 `{{占位符}}` 原样输出，不做参数抽取**。从中文意图抽取参数填槽本质是 NLU 任务，关键词匹配层没有这个能力；占位符上屏由用户手改，与 v0.1"替换后用户可微调、执行权永远在用户"的交互契约一致。被拒绝的备选：正则猜参（误填比不填更危险）。`[假设]`此限制可接受，T-I-43 锁定行为。
- **决策 5：`-x` 的解释语言 auto 判定 = CJK 检测 + locale 回退**。§13 决策原文是"跟随意图语言"，但 `-x` 输入是命令（ASCII 为主、不构成语言信号），`[假设]`落地为：配置显式指定 > 输入含 CJK > `LC_ALL`/`LANG` 以 zh 开头 → 中文，否则英文。被拒绝的备选：固定中文（英文用户不友好）、跟随系统不检测输入（生成路径的"中文意图→中文解释"语义无法满足）。
- **决策 6：`-x` 的 LLM 综合一次性调用（全部段 + kb 素材一次喂入），不为每段单独调用**。N 段 N 次调用意味着 N 倍 1~3s 延迟；单次调用用 JSON schema 约束逐段输出，解析失败按行兜底对齐段序（复用 v0.1 两级解析哲学）。被拒绝的备选：逐段调用（延迟不可接受）、不喂 kb 素材（浪费第 2 层数据，解释质量无锚点）。
- **决策 7：TUI 入口为 `hlp --tui [意图]` + 裸 `hlp`（TTY 时）**。`--one-line` 契约是 shell 集成的生命线，不可让"裸 hlp 带意图"歧义化——v0.1 已定裸意图 = one-line；裸 `hlp` 无参数此前是 clap 用法错误，TTY 下复用为 TUI 入口无冲突。被拒绝的备选：独立 `hlp-tui` 二进制（分发复杂化）、`hlp` 带意图进 TUI（破坏 v0.1 契约）。
- **决策 8：TUI 卡片的逐段解释与生成同一次 LLM 调用（`want_explanation` 扩展 schema）**，而非生成后再调一次 `-x` 流程。省一次 1~3s round-trip；schema 扩展经 ollama `format` 下发，解析失败时 segments 为空、TUI 提供 X 键重新获取（走 explain 模块），双保险。被拒绝的备选：两次调用（延迟翻倍）、Provider trait 加 history 参数（refine 用 prompt 拼装即可承载，trait 保持稳定）。
- **决策 9：dry-run 执行一律 argv 直执、不经 shell，参数含特殊字符即拒绝**。`rm -rf x; evil` 这类注入在 `sh -c` 拼接下会变成真实执行——dry-run 的存在前提是"绝不执行原命令语义"，宁可预览能力受限（glob 不展开）也不开注入面。被拒绝的备选：`sh -c` + 字符黑名单（黑名单难完备）、允许 glob（必须经 shell，与前述冲突；列为已知局限写入遗留风险）。
- **决策 10：dry-run 变换表内置代码（5 条规则），不开放用户配置**。变换规则直接决定哪条命令会被执行，开放配置等于开放一条执行路径，规则增减应走代码评审。被拒绝的备选：dryrun.toml 用户自定义（安全面失控）。
- **决策 11：复制功能用 OSC52 写 `/dev/tty`，不引入 arboard**。OSC52 在主流终端与 SSH 会话可用，零新依赖；clipboard crate 在 Linux 需要 X11/Wayland 运行时探测，失败模式更多。被拒绝的备选：arboard（新依赖 + 会话类型分支）。
- **决策 12：daemon 协议升 v2 加 Explain op，不为 explain 单独开端口/通道**。复用既有 socket 与"版本不匹配 → protocol 错误 → 回退直连"的韧性链；旧 daemon 残留不会出错只是 explain 走直连。被拒绝的备选：explain 永远直连（浪费 daemon 的 Provider 保温）、协议内联版本协商（复杂度不值）。

## 10. 遗留风险（实现模型最易搞错的点）

1. **`split.rs` 的引号/转义边界**：`\|`、单双引号嵌套、未闭合引号是三个独立陷阱；实现必须按字符状态机扫描（Normal/SingleQuote/DoubleQuote/Escape 四态），用正则切分必错。T-U-51~53 是守门测试。
2. **dry-run 的 glob 不展开是语义差距**：`rm -rf *.bak` 的预览（`ls -ld -- '*.bak'`）只显示字面量而非匹配到的文件列表，预览集 ≠ 实际删除集。实现时必须在预览首行固定标注"glob 未展开"，`--dry-run` 的 stdout 协议首行文案按 §3.4 逐字实现，不许自由发挥。
3. **tldr.zip 结构漂移**：上游目录布局或 frontmatter 变化时，`parse_page` 批量失败。fetch 层必须实现"skipped 超过总数 50% → 判定结构漂移，整体报错退出 6"的熔断，而不是静默导入一个近乎空的语料库。
4. **TUI 依赖污染冷启动**：ratatui/crossterm 若在 main.rs 顶层初始化或静态构造，`--one-line` 路径启动会变慢。TUI 的一切初始化必须只在 `tui::run` 内发生；T-I-41 的 200ms 计时断言是守门测试。
5. **协议 v1/v2 混跑的explain 延迟**：用户升级二进制后，旧 v0.3 daemon 可能仍在运行（5 分钟空闲才退出），此间 explain 每次都走"protocol 错误 → 回退直连"，表现为 explain 莫名变慢。README 升级说明必须写明：`hlp kb-update` 后建议 `pkill -f "hlp daemon"` 或等待旧实例自然退出。
6. **`-x` 段对齐兜底**：LLM 返回的 segments 数与拆段数不一致时，禁止按 LLM 段序渲染——必须以本地 split 结果为骨架，LLM 段按序对位填充、缺段用 kb 标注、多段丢弃（T-U-67 守门）。实现者容易直接渲染 LLM 原始返回，导致命令段与解释错位。
